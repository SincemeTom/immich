## 二、服务器：群晖照片（Synology Photos）相册同步

纯服务器功能（网页上设置），手机 App 不用改。

已定的原则（账户隔离）：

- 每个 Immich 用户绑定**自己的**群晖账号，只同步**自己是所有者**的相册
- 别人共享给我的群晖相册：对方没有 Immich 账号，或对应不上，**先不同步**；等对方有了 Immich 账号、绑定自己的群晖后，由他那边同步过来，再在 Immich 里共享给我
- 现有数据：你的账号有 49 个相册

要做的：

- [x] 方案确认（2026-11-04）：
  - 读取：群晖照片 Web API，用户用自己的群晖账号登录；群晖 → Immich 单向，群晖那边一样都不改
  - 对照片：外部图库路径优先；对不上再按文件名 + 拍摄时间 + 大小找（例如手机备份上来的）；仍对不上的列进同步报告
  - 路径（2026-11-04 确认）：正式服的外部图库读写挂载群晖的 `/volume1/homes/<账号>/Photos`。群晖给的是相对这个目录的路径，所以在该用户自己的外部图库里，找路径以“相对路径 + 文件名”结尾的照片，不用填路径前缀
  - 删除：群晖删了相册、或把照片移出相册，Immich 跟着删 / 移出；只动同步建的相册、同步加进去的照片，在 Immich 里自己加进这些相册的照片保留；照片本身从不删
  - 频率：网页上“立即同步”，另外每天凌晨 3 点自动同步，时间可改
  - 开工前的数据：`macos/scripts/synology_photos_probe.py` 读一次真实的相册、照片、文件夹和共享信息，原始数据留在仓库外（`~/Documents/immich-scratch/synology/`），只把去掉名字的结构记进 `verification/`
- [x] 用户设置里绑定群晖（2026-11-04）：账号设置 → 群晖照片，填地址、账号、密码，先登录验证再保存；密码存 macOS 钥匙串；测试连接、解除绑定；两步验证只需输一次验证码（[verification/synology-account.md](verification/synology-account.md)）。还差在正式服用真实账号绑定一次
- [ ] SSO 能否代替密码：`macos/scripts/synology_sso_probe.py` 试授权码换群晖会话、token 调群晖照片，能拿到会话就隔天用 `--recheck` 看还能不能用。能用且隔夜有效，再加“用 SSO 授权”的绑定方式；否则只用密码
- [ ] 同步相册：建相册、加照片、相册名和封面；群晖里删掉的相册 / 移出的照片怎么处理
- [ ] 群晖上的共享关系：所有者和被共享人都已绑定时，在 Immich 里按对应权限共享（对应五档权限）
- [ ] 对不上的照片和相册列出来，不静默丢掉
- [ ] 端到端验证：你的 49 个相册，在挂着真实外部图库的正式服上做（开发机只有测试照片）
