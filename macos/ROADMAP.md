## 二、服务器：群晖照片（Synology Photos）相册同步

纯服务器功能（网页上设置），手机 App 不用改。

已定的原则（账户隔离）：

- 每个 Immich 用户绑定**自己的**群晖账号，只同步**自己是所有者**的相册
- 别人共享给我的群晖相册：不从我这边同步；对方用 SSO 登录 Immich 并绑定自己的群晖后，由他那边同步过来，按群晖的权限共享给我
- 现有数据：你的账号有 49 个相册

要做的：

- [x] 方案确认（2026-11-04）：
  - 读取：群晖照片 Web API，用户用自己的群晖账号登录；群晖 → Immich 单向，群晖那边一样都不改
  - 对照片：外部图库路径优先；对不上再按文件名 + 拍摄时间 + 大小找（例如手机备份上来的）；仍对不上的列进同步报告
  - 路径（2026-11-04 确认）：正式服的外部图库读写挂载群晖的 `/volume1/homes/<账号>/Photos`。群晖给的是相对这个目录的路径，所以在该用户自己的外部图库里，找路径以“相对路径 + 文件名”结尾的照片，不用填路径前缀
  - 删除：群晖删了相册、或把照片移出相册，Immich 跟着删 / 移出；只动同步建的相册、同步加进去的照片，在 Immich 里自己加进这些相册的照片保留；照片本身从不删
  - 频率：网页上“立即同步”，另外每天凌晨 3 点自动同步，时间可改
  - 开工前的数据：`macos/scripts/synology_photos_probe.py` 读一次真实的相册、照片、文件夹和共享信息，原始数据留在仓库外（`~/Documents/immich-scratch/synology/`），只把去掉名字的结构记进 `verification/`
- [x] 共享成员和别人的照片怎么对应（2026-11-04 确认）：
  - 认人：群晖共享成员只按两种方式对应到 Immich 用户：① 用群晖 SSO 登录过 Immich，Immich 记下的 `oauthId` 就是群晖登录名，和共享列表里成员的登录名一致（不分大小写）；② 他在 Immich 里绑定了群晖账号，群晖用户 ID 一致。**不按名字或邮箱对应**，也不列“建议”
  - 权限：对应上的成员按 查看 / 下载 / 上传 → 仅查看 / 可下载 / 可编辑 共享；对应不上的先挂起，报告里只写人数，他用 SSO 登录或绑定后，下一次同步补上
  - 别人加进我相册的照片：照片仍是他的，同步代他把他自己的照片加进我的相册，和他在 Immich 里作为可编辑成员自己加的一样。只在**他自己**的库里找：他绑定了群晖账号时，用他的会话读到文件夹路径，按路径找；只用 SSO 登录时，按文件名 + 大小 + 拍摄时间找，同时对上多张的进报告；还没有 Immich 账户的先挂起
  - 前提：他的外部图库在 Immich 里的所有者是他本人
  - 现有数据（只读对照）：14 个共享成员里 3 个已用 SSO 登录 Immich；别人的 3049 项里 3044 项属于其中 2 人，另 5 项的主人还没有 Immich 账户
- [x] 用户设置里绑定群晖（2026-11-04）：账号设置 → 群晖照片，填地址、账号、密码，先登录验证再保存；密码存 macOS 钥匙串；测试连接、解除绑定；两步验证只需输一次验证码（[verification/synology-account.md](verification/synology-account.md)）。还差在正式服用真实账号绑定一次
- [ ] SSO 能否代替密码：`macos/scripts/synology_sso_probe.py` 试授权码换群晖会话、token 调群晖照片，能拿到会话就隔天用 `--recheck` 看还能不能用。能用且隔夜有效，再加“用 SSO 授权”的绑定方式；否则只用密码
- [x] 同步相册（2026-11-04）：自己的相册建成 Immich 相册，照片按路径从自己的外部图库里找；跟着群晖改名、换封面、增减照片、删相册，只动同步建的相册和加的照片；每天定时（默认 03:00，可改）和立即同步，账号设置里显示报告（[verification/synology-album-sync.md](verification/synology-album-sync.md)）。还差在正式服用真实账号同步一次，看命中率
- [x] 别人加进我相册的照片（2026-11-04）：代他加进来，只在他自己的库里找，绑定了账号的按路径、否则按文件名 + 大小 + 时间；对上多张、等主人加入的进报告（[verification/synology-album-sharing.md](verification/synology-album-sharing.md)）。还差在正式服用真实账号同步一次
- [x] 群晖上的共享关系（2026-11-04）：对应上的成员按 查看 / 下载 / 上传 → 仅查看 / 可下载 / 可编辑 共享，跟着群晖改角色、取消共享；只动同步加的成员，手动加的不动；对应不上的报告里只写人数（[verification/synology-album-sharing.md](verification/synology-album-sharing.md)）
- [x] 对不上的照片和相册列出来，不静默丢掉（2026-11-04）：没找到、对上多张、主人不在 Immich 里的照片，没建、读不到的相册，每次同步整份记下，网页上按相册查看、下载 CSV；自己的照片按路径找不到时，再按文件名 + 大小 + 时间在自己的全部照片里找（[verification/synology-unmatched.md](verification/synology-unmatched.md)）
