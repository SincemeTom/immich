## v3.3.5-mac.9（2026-11-05）

基于上游 v3.3.5。

**新功能**

- 绑定群晖账号，为同步群晖照片的相册做准备：网页 账号设置 → 群晖照片，填群晖地址、账号和密码。保存前会先登录一次，确认能读到群晖照片，并显示有多少个相册；之后可以随时“测试连接”或解除绑定。密码存在服务器的 macOS 钥匙串里，不存进数据库；开了两步验证的账号只需输一次验证码。每个用户只能绑定自己的账号，同一个群晖账号不能绑给两个 Immich 用户。只读群晖，不改动群晖上的任何内容（[synology-account.md](verification/synology-account.md)）
- 同步群晖照片的相册：绑定了群晖账号后，你在群晖照片里自己的每个相册，都会同步成你在 Immich 里的一个相册，照片按路径从你自己的外部图库里找到（外部图库要挂载群晖上你的 Photos 目录）。每天定时同步，默认凌晨 3 点，可以改时间或关掉；也可以在 账号设置 → 群晖照片 里点“立即同步”，下面会显示上次同步建了几个相册、找到多少张照片，以及没找到的照片。群晖上改了相册名字、换了封面、加了或移出照片、删了相册，下次同步时 Immich 跟着变；但只动同步自己建的相册、只移出同步自己加进去的照片，你在 Immich 里自己加进去的照片保留，照片本身从不删除（[synology-album-sync.md](verification/synology-album-sync.md)）
- 群晖相册的共享成员和别人加的照片也同步过来（[synology-album-sharing.md](verification/synology-album-sharing.md)）：
  - 群晖上共享给了谁，Immich 里就共享给对应的用户：查看 → 仅查看，下载 → 仅查看、可下载，上传 → 可编辑。群晖上改了角色、取消了共享，下次同步跟着变；
  - 只认两种人：在 Immich 里绑定了群晖账号的，或用群晖登录过 Immich 的，不按名字或邮箱猜。还对应不上的，同步结果里只显示有几位，他们加入后下次同步补上；
  - 别人加进你相册的照片，从他自己的库里找到后加进来（照片仍是他的）：他绑定了群晖账号时按路径找，否则按文件名、大小和拍摄时间找；
  - 只改动同步自己加的成员。你在 Immich 里自己加的成员不动；同步加的成员被你移出后，不会再加回来
- 群晖同步对不上的相册和照片都列出来（[synology-unmatched.md](verification/synology-unmatched.md)）：账号设置 → 群晖照片 → 上次同步，点“查看列表”按相册看，或“下载列表”存成 CSV。列出没找到的照片、按名字对上不止一张的照片、主人还不在 Immich 里的照片，以及没建的相册和群晖没列出照片的相册；别人的照片只标“别人加的”，不写是谁。另外，自己的照片在外部图库的对应路径下找不到时，再按文件名、大小和拍摄时间在你的全部照片里找，例如手机上传的

**改进**

- 存储空间按实际情况显示（[m1-storage-space.md](verification/m1-storage-space.md)）：
  - 服务器总量包括挂载的网络共享。同一个群晖卷上的几个共享只算一次；没连上的不算，并提示有几个没算进去。不想算可以在 管理 → 设置 → 服务器 里关掉；
  - 网页左下角显示的已用是你自己的照片，上传的加上你外部图库的；上限是你的配额，没有配额时是服务器总量。鼠标悬停可以看到上传和外部图库各占多少。配额仍只限制上传：外部图库再大，也不会因此不能上传；
  - 管理 → 服务器状态 新增“存储空间”：服务器总量，以及本机和每个网络共享各用了多少、还剩多少、是否计入；
  - 手机 App 不用更新：没有配额的用户，看到的也是自己的用量和服务器总量。有配额的用户，App 里仍只算上传的

**升级注意**

- 数据库有一处迁移（新建四张表，记录同步建的相册、加进去的照片、共享的成员和对不上的相册和照片），升级时自动完成
- 接口 `GET /server/storage` 的 `diskUse` 改为当前用户自己的用量（上传 + 外部图库），`diskSize` 和 `diskAvailable` 改为服务器总量和可用空间（包括网络共享）。读这几个字段算整台服务器用了多少的脚本，改读管理员接口 `GET /server/storage/details`

## v3.3.5-mac.7（2026-11-03）

基于上游 v3.3.5。

**改进**

- 位置推断的规则放宽，也更好理解（[m4-location-inference.md](verification/m4-location-inference.md)）：
  - 夹在中间：前后都有带位置的照片、且两张相距不超过 1 公里时，每边最多 3 小时（原来 1 小时），用时间更近的那张；
  - 紧挨着：只有一侧有带位置的照片，或前后两张相距较远时，最近那张在 30 分钟内就用它的位置（原来不推断）；
  - 共享照片：先只用自己的照片；推断不出来时，才用和这张照片在同一个共享相册里的别人的照片（原来是你所在的任何相册里的别人的照片，都参与推断）。照片移出相册后，用它推断的位置会重新推断；
  - 详情面板的"推断"下面显示依据，例如"根据 10:00 拍的照片"；用的是别人的照片时，显示是谁的；
  - 管理 → 设置 → 元数据 里可以调这三个数（分钟、分钟、米）。改了以后会自动按新规则全部重新推断，升级后也会重新推断一遍

**修复**

- 共享相册里查看别人的照片时，网页控制台不再反复报 400：
  - 别人的照片属于堆叠时，网页会去读这个堆叠，但服务端只让堆叠的主人读，所以报错。现在不是自己的照片就不去读（上游原有问题）
  - 在查看器里把相册最后一张照片移出后，查看器关闭时会去定位这张已经看不到的照片，所以报错。现在不再定位

**升级注意**

- 数据库有一处迁移（记录推断位置的来源照片），升级时自动完成
- 升级后服务端启动时按新规则把所有照片重新推断一遍位置，照片多时要跑一阵，期间照常使用。原来推断的位置会换成新规则的结果，记录下来源；本人清除过的照片仍然不推断

## v3.3.5-mac.6（2026-11-03）

基于上游 v3.3.5。

**新功能**

- 没有位置的照片自动推断位置：前后 1 小时内各有一张有位置的照片、且两张相距不超过 1 公里时，用时间更近的那张的位置，地图、按地点搜索、中文地名都能用。也参考共享给你的相册里别人拍的照片。只保存在 Immich 里，不改原文件；详情面板的地点下显示"推断"，可以点 × 清除，清除后不再推断。管理 → 设置 → 元数据 里可以关掉或清除全部，默认开启；升级后自动对已有照片跑一遍（[m4-location-inference.md](verification/m4-location-inference.md)）
- 共享相册权限更细：
  - 成员分仅查看、可下载、可编辑、可管理四档；
  - 新加的查看者默认只能看、不能下载原图；编辑者只能添加、移除自己的照片；
  - 邀请和移除成员、改权限、改相册名和描述、选封面、建共享链接，只有管理者和所有者能做；删除相册只有所有者能做；
  - 在相册的 选项 → 用户 里设置；
  - 已有相册升级后不变：原来的查看者仍能下载，原来的编辑者成为管理者；
  - 官方手机 App 仍显示查看者 / 编辑者，在 App 里改角色不会去掉已有的下载、管理权限（[m4-album-permissions.md](verification/m4-album-permissions.md)）

**修复**

- 内容分析的并发调高后，视频语音识别不再卡住：原来同时识别的视频数一达到 CPU 核心数（如 Mac mini M4 的 10），识别程序就会卡死，任务一直显示"正在运行"，30 分钟后一起失败。现在同时最多识别 2 段视频，其余排队；照片不受影响，调高并发照样加快照片的分析（[m4-vision-speech-deadlock.md](verification/m4-vision-speech-deadlock.md)）
- 视频语音识别的超时按视频时长计算（10 分钟加上视频时长，最多 2 小时），不再固定 30 分钟；一段视频超时也不会让同时在处理的其他照片和视频一起失败
- 安装、升级后模型预热期间，设置人物封面、上传照片等操作马上生效：原来预热期间所有后台任务都要排队，预热结束时服务还要重启一次，网页收不到"已完成"的通知，要手动刷新才看到结果，重启那几秒内的操作还会报错。现在预热期间服务不重启，只有智能搜索、人脸检测、文字识别等模型就绪后再做，其余任务照常（[m4-person-cover-during-warmup.md](verification/m4-person-cover-during-warmup.md)）

**升级注意**

- 数据库有两处迁移（推断位置的标记、相册成员的下载和管理权限），升级时自动完成
- 升级后服务端启动时自动对已有照片推断一遍位置，照片多时要跑一阵，期间照常使用；不想要可以在 管理 → 设置 → 元数据 里关掉，再点"清除推断的位置"
- 共享相册：已有成员能做的事不变。之后新加的查看者默认不能下载原图，需要时在相册的 选项 → 用户 里改为"可下载"

基于上游 v3.3.5，第一个正式版。

- 不需要 Docker、Homebrew 的 `.pkg` 安装包：自带 PostgreSQL、VectorChord、Valkey、Node.js、Python、ffmpeg、libvips 等全部依赖；可接管一键安装版的数据（[m3-pkg.md](verification/m3-pkg.md)）
- 机器学习用 CoreML；智能搜索默认用中英日多语言模型 XLM-Roberta-Large-ViT-H-14，安装时预先准备好模型（[m1-clip-model.md](verification/m1-clip-model.md)）
- 视频转码用 Apple 媒体引擎（VideoToolbox），HDR 亮度与软件转码一致（[m2-videotoolbox.md](verification/m2-videotoolbox.md)）
- 网页上挂载群晖 NFS 共享，开机自动挂载、断线自动重连；缩略图、转码视频、备份、原图可以放到群晖（[m1-network-shares.md](verification/m1-network-shares.md)、[m1-storage-locations.md](verification/m1-storage-locations.md)）
- 外部库：按内容查重，不再被手机备份重复上传；群晖断开时不删照片记录；删除外部库立即对所有成员生效
- 用户隔离加固：路径相关的操作只限管理员，非管理员只能访问分配给自己的外部库
- 自动堆叠（连拍、RAW+JPG、编辑版、相似照片）；RAW 默认用相机内嵌预览；视频和实况照片可旋转、镜像
- 修复上游问题：数据库备份路径和空备份、实况照片配对错误、编辑顺序、PP-OCRv5_server 在 CoreML 上编译失败等
