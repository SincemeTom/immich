# 更新记录

Immich macOS 原生版（非官方）的各个版本。版本号是 `<上游 Immich 版本>-mac.<序号>`，每个版本对应一个 git 标签，发布流程见 [RELEASING.md](RELEASING.md)。这个版本基于上游 Immich 修改，改动的验证记录在 [verification/](verification/README.md)。

## 未发布

**修复**

- 共享相册里查看别人的照片时，网页控制台不再反复报 400：
  - 别人的照片属于堆叠时，网页会去读这个堆叠，但服务端只让堆叠的主人读，所以报错。现在不是自己的照片就不去读（上游原有问题）
  - 在查看器里把相册最后一张照片移出后，查看器关闭时会去定位这张已经看不到的照片，所以报错。现在不再定位

## v3.3.5-mac.6（2026-11-03）

基于上游 v3.3.5。

**新功能**

- 没有位置的照片自动推断位置：前后 1 小时内各有一张有位置的照片、且两张相距不超过 1 公里时，用时间更近的那张的位置，地图、按地点搜索、中文地名都能用。也参考共享给你的相册里别人拍的照片。只保存在 Immich 里，不改原文件；详情面板的地点下显示"推断"，可以点 × 清除，清除后不再推断。管理 → 设置 → 元数据 里可以关掉或清除全部，默认开启；升级后自动对已有照片跑一遍（[m4-location-inference.md](verification/m4-location-inference.md)）
- 共享相册权限更细：
  - 成员分仅查看、可下载、可编辑、可管理四档；
  - 新加的查看者默认只能看、不能下载原图；编辑者只能添加、移除自己的照片；
  - 邀请和移除成员、改权限、改相册名和描述、选封面、建共享链接，只有管理者和所有者能做；删除相册只有所有者能做；
  - 在相册的 选项 → 用户 里设置；
  - 已有相册升级后不变：原来的查看者仍能下载，原来的编辑者成为管理者；
  - 官方手机 App 仍显示查看者 / 编辑者，在 App 里改角色不会去掉已有的下载、管理权限（[m4-album-permissions.md](verification/m4-album-permissions.md)）

**修复**

- 内容分析的并发调高后，视频语音识别不再卡住：原来同时识别的视频数一达到 CPU 核心数（如 Mac mini M4 的 10），识别程序就会卡死，任务一直显示"正在运行"，30 分钟后一起失败。现在同时最多识别 2 段视频，其余排队；照片不受影响，调高并发照样加快照片的分析（[m4-vision-speech-deadlock.md](verification/m4-vision-speech-deadlock.md)）
- 视频语音识别的超时按视频时长计算（10 分钟加上视频时长，最多 2 小时），不再固定 30 分钟；一段视频超时也不会让同时在处理的其他照片和视频一起失败
- 安装、升级后模型预热期间，设置人物封面、上传照片等操作马上生效：原来预热期间所有后台任务都要排队，预热结束时服务还要重启一次，网页收不到"已完成"的通知，要手动刷新才看到结果，重启那几秒内的操作还会报错。现在预热期间服务不重启，只有智能搜索、人脸检测、文字识别等模型就绪后再做，其余任务照常（[m4-person-cover-during-warmup.md](verification/m4-person-cover-during-warmup.md)）

**升级注意**

- 数据库有两处迁移（推断位置的标记、相册成员的下载和管理权限），升级时自动完成
- 升级后服务端启动时自动对已有照片推断一遍位置，照片多时要跑一阵，期间照常使用；不想要可以在 管理 → 设置 → 元数据 里关掉，再点"清除推断的位置"
- 共享相册：已有成员能做的事不变。之后新加的查看者默认不能下载原图，需要时在相册的 选项 → 用户 里改为"可下载"

## v3.3.5-mac.5（2026-11-02）

基于上游 v3.3.5。

**新功能**

- 内容分析（Apple Vision，在神经网络引擎上运行，不用下载模型）：照片按内容自动打中文标签，放在"自动"下，如"自动/动物/猫""自动/食物/蔬菜/西兰花"，可在标签页按类浏览，删掉"自动"标签即可全部去掉；截图打"自动/截图"，二维码打"自动/文档/二维码"；每张照片保存美学分，留给以后选堆叠封面。设置在 管理 → 设置 → 机器学习 → 内容分析，截图自动归档默认关闭（[m4-vision-content.md](verification/m4-vision-content.md)）
- 自动堆叠的封面：规则相同时（连拍、相似照片）选拍得更好的一张（美学分），你自己选过封面的不动
- macOS 26 上还会：识别视频里说的话，按"照片中的文字"搜索时也能搜到（语言在设置里选，默认普通话）；识别文档（"自动/文档""自动/文档/表格"）、镜头脏污（"自动/质量/镜头脏污"）。**低于 macOS 26 时这几项自动不运行**，升级到 26 后重启 Immich 自动补做
- 已有照片在升级后服务端启动时自动开始分析（5 万张约 40 分钟），不用手动点
- 新识别的人物可以默认隐藏：管理 → 设置 → 机器学习 → 人脸识别 → "新识别的人物默认隐藏"，默认关闭

**修复**

- 设特色照片后人物头像几秒内就换：原来后台有导入、扫描任务时，头像任务要排到最后；网页上的头像也不会重新加载，要刷新整页才看得到
- "隐藏未命名的人物"隐藏全部未命名人物：原来只隐藏页面上已经加载的前 500 个
- 照片在 NAS 上时，编辑（旋转）保存不再误报"应用编辑失败"：超过 30 秒提示"正在后台处理"，处理完照片自动更新（[m1-edit-nfs-timeout.md](verification/m1-edit-nfs-timeout.md)）
- macOS 26 起的文档、镜头脏污识别按实测校准：Vision 给的文档把握度始终为 0，改为按识别到的文字判断；白墙、背景虚化不再被当成镜头脏污

**升级注意**

- 升级后服务端启动时自动开始内容分析，已有照片较多时要跑一阵（5 万张约 40 分钟），期间照常使用
- 打包机升级到 macOS 27 后，包仍然支持 macOS 15 及以上（[RELEASING.md](RELEASING.md)，"Homebrew on a newer macOS"）

## v3.3.5-mac.3（2026-11-01）

基于上游 v3.3.5。

**修复**

- mac.2 的安装包在 Installer 里几秒就报"安装失败"、什么都没装：安装脚本找安装用户时，`ps` 的输出超过管道缓冲区、读取一方提前退出，脚本收到 SIGPIPE 退出。是否出现取决于 Installer 在进程表里的位置，机器越忙越容易失败（[m4-pkg-postinstall-sigpipe.md](verification/m4-pkg-postinstall-sigpipe.md)）。同类写法全部改掉；安装脚本开头先记日志，失败时记下行号

**许可与声明**

- 安装器新增许可页（中英文），欢迎页写明这是非官方版本
- 安装包附带全部第三方组件的许可全文和清单（`licenses/`），打包时一并留档 GPL、LGPL 组件的源代码
- 网页"帮助"和"关于"里指向这个版本自己的源代码（具体提交）和文档
- 首页、`macos/README.md`、[LEGAL.md](LEGAL.md)：许可、模型限制、商标、不担保

## v3.3.5-mac.2（2026-11-01）

基于上游 v3.3.5。

**新功能**

- 机器学习模型改用上游的 v2 导出：在本机转成 fp16，交给神经网络引擎（ANE）运行。智能搜索、人脸快约一倍，OCR 的文字检测再快近一倍；整台 Mac 多占的内存从 6.0 GB 降到 1.6 GB；搜索、人脸、OCR 的结果与原来一致（[m4-ml-ane.md](verification/m4-ml-ane.md)）
- 升级后原来的搜索索引和人脸分组照常使用，不用重建；旧模型及其编译缓存在准备好新模型后自动删除（约 20 GB）

**修复**

- 安装器报"安装失败"：准备模型超过了 Installer 给安装脚本的 600 秒。改为在后台准备，安装约一分钟结束；准备期间网页、App、上传正常，缩略图、搜索、人脸、文字识别排队，准备好后自动处理（[m4-pkg-postinstall-timeout.md](verification/m4-pkg-postinstall-timeout.md)）
- 安装包里混装了两个 OpenCV，16 位模型下人脸和文字识别全部失败（3.3.5-mac.1 用的是 32 位模型，不受影响）
- 模型还在准备时再装一次会出错；中途停止准备会多留一份 2.8 GB 的 CPU 版模型

**升级注意**

- 从 mac.1 升级：第一次准备新模型约 10–15 分钟（M4），期间服务器会重启一次

## v3.3.5-mac.1（2026-10-31）

基于上游 v3.3.5，第一个正式版。

- 不需要 Docker、Homebrew 的 `.pkg` 安装包：自带 PostgreSQL、VectorChord、Valkey、Node.js、Python、ffmpeg、libvips 等全部依赖；可接管一键安装版的数据（[m3-pkg.md](verification/m3-pkg.md)）
- 机器学习用 CoreML；智能搜索默认用中英日多语言模型 XLM-Roberta-Large-ViT-H-14，安装时预先准备好模型（[m1-clip-model.md](verification/m1-clip-model.md)）
- 视频转码用 Apple 媒体引擎（VideoToolbox），HDR 亮度与软件转码一致（[m2-videotoolbox.md](verification/m2-videotoolbox.md)）
- 网页上挂载群晖 NFS 共享，开机自动挂载、断线自动重连；缩略图、转码视频、备份、原图可以放到群晖（[m1-network-shares.md](verification/m1-network-shares.md)、[m1-storage-locations.md](verification/m1-storage-locations.md)）
- 外部库：按内容查重，不再被手机备份重复上传；群晖断开时不删照片记录；删除外部库立即对所有成员生效
- 用户隔离加固：路径相关的操作只限管理员，非管理员只能访问分配给自己的外部库
- 自动堆叠（连拍、RAW+JPG、编辑版、相似照片）；RAW 默认用相机内嵌预览；视频和实况照片可旋转、镜像
- 修复上游问题：数据库备份路径和空备份、实况照片配对错误、编辑顺序、PP-OCRv5_server 在 CoreML 上编译失败等
