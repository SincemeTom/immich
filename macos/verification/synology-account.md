# 群晖照片相册同步：绑定群晖账号

- 分支：`mac/feat/synology-albums`
- 日期：2026-11-04
- 结论：每个用户在 账号设置 → 群晖照片 里绑定自己的群晖账号。先登录验证，成功后才保存；密码放在服务器的 macOS 钥匙串里，数据库里只有地址、账号名和上次连接的结果。开了两步验证的账号只需输一次验证码。服务器单元测试 87 项、网页 8 项通过；钥匙串和真实群晖的连通各实测一遍。用真实账号绑定还没做，见文末

## 怎么做的

| 部分 | 做法 |
|---|---|
| 接口 | `GET` / `PUT` / `DELETE /synology/account`，`POST /synology/account/test`；每个用户只能动自己的，权限同个人设置（`userPreference.read` / `update`） |
| 绑定 | 读 `SYNO.API.Info` → 登录 `SYNO.API.Auth`（DSM 支持就用 v7，否则 v6）→ `SYNO.Foto.UserInfo me` → 数相册（`Browse.Album list v2`，每页 500）→ 登出。哪一步失败都不保存，已绑定的账号保持原样 |
| 密码 | 钥匙串里的通用密码项，服务名 `Immich Synology`，账户名是 Immich 用户 ID，里面是 `{"password", "deviceId"}` |
| 其他信息 | `system_metadata` 的 `synology-accounts`：地址、是否校验证书、账号名、群晖照片里的用户 ID（照片的 `owner_user_id`、共享的 `db_id` 都是它）、DSM 用户 ID、上次连接时间和结果 |
| 同一个群晖账号 | 同一台群晖上只能绑给一个 Immich 用户（按群晖照片用户 ID 判断，不比名字） |
| 改设置 | 地址和账号都没变时，密码可以留空，沿用钥匙串里的 |
| 删除用户 | 跟着删钥匙串项和绑定信息；删失败只记日志，不影响删除用户 |
| 只在 macOS 原生版 | 和网络共享一样看 `IMMICH_NETWORK_SHARES_LOCATION`；官方服务器和 Docker 版没有这个菜单，接口返回 400 |

### 钥匙串

服务器是登录用户的 LaunchAgent，它的登录钥匙串是解锁的。用 `/usr/bin/security` 读写，实测：

| 情况 | 结果 |
|---|---|
| 从临时 LaunchAgent 写入、读出、删除 | 都成功，没有弹窗，也不用输密码 |
| 密码放在命令行参数里 | 不放，`ps` 能看到命令行参数。`security ... -w` 不带值时从标准输入读，要输两遍 |
| 从终端启动服务器（开发时） | `security` 会改读终端，不读标准输入，所以用独立会话启动（`detached`），没有控制终端 |
| 引号、反斜杠、`$`、反引号、中文 | 都能原样读回。但非 ASCII 字符读回时会被打成十六进制，分不清原来是不是十六进制，所以写入前转成 base64 |
| 两遍输入不一致 | `security` 会存成空值，所以写完再读一遍核对 |
| 没有这一项 | 退出码 44，当作“没有”，不算出错 |
| 10 秒没响应 | 杀掉进程，报错 |

真实钥匙串跑了一遍写入、读出、覆盖、删除和重复删除，测试项已删除。

### 两步验证

只有管理员账号开了两步验证，也只在第一次登录时要验证码：

- 登录返回 403 时，网页多出“两步验证码”一栏，输入后再登录一次，带 `otp_code` 和 `enable_device_token=yes`；
- 群晖返回的 `did` 存进钥匙串，以后登录带 `device_id`，就不用再要验证码；
- 换了地址或账号时，旧的 `did` 不带过去。

### 错误

网页按原因给出提示，并显示群晖或系统的原话：

| 原因 | 来自 |
|---|---|
| 连不上、证书不受信任、不是群晖 | 网络错误码；HTTP 状态不是 200、回的不是 JSON、对 HTTP 端口说 HTTPS |
| 没装群晖照片 / 账号不能用 | `SYNO.API.Info` 里没有 `SYNO.Foto.*`，或 `UserInfo me` 失败 |
| 密码错、账号停用、不允许登录、要验证码、验证码错、要先设两步验证、IP 被封、密码过期 | 登录错误码 400、401、402、403、404、406、407、408–410（DSM 登录接口指南） |
| 已被别人绑定、钥匙串出错、其他 | 服务器自己 |

请求一律用 POST 表单，密码不进 URL；不跟随跳转；30 秒超时；回包超过 32 MB 就断开。

## SSO

群晖 SSO Server 的 OpenID 配置只提供 `authorization_code` 和 `implicit` 两种授权方式，`scope` 只有 `openid`、`email`、`groups`，没有 refresh token。能不能用它换到群晖照片能用的会话、会话能保持多久，用 `macos/scripts/synology_sso_probe.py` 测（只读）：

1. 授权码直接交给 `SYNO.API.Auth login` v7（`type=code`，PKCE）；
2. 授权码换成 access token，再分别用 `Authorization: Bearer`、当作 `_sid`、交给登录接口三种方式调群晖照片；
3. 哪种能拿到会话，就保留这个会话，第二天用 `--recheck` 看还能不能用。

结果出来前，绑定只用密码。
