# 存储空间：服务器总量包括网络共享，用户用量包括外部图库

- 分支：`mac/feat/storage-space`
- 日期：2026-11-04
- 结论：
  - 服务器总量 = 图库所在的磁盘 + 服务器挂载的网络共享。同一个存储卷只算一次；没连上的共享不算，并提示有几个没算进去。设置里可以关掉。
  - 每个用户左下角显示的已用 = 自己上传的 + 自己外部图库的；上限有配额时是配额，没有配额时是服务器总量。配额只用于显示上限，判断能不能上传仍只算上传的照片，和上游一样。
  - 管理后台的服务器状态新增“存储空间”：服务器总量，以及本机和每个网络共享的用量和状态。
  - 测试：服务器单元测试新增 16 项、数据库测试新增 2 项、网页测试新增 5 项，全部通过。还没在正式服上用真实的群晖核对，见文末。

## 怎么做的

| 部分 | 做法 |
|---|---|
| 读共享的容量 | 在每分钟的网络共享检查里读：先读目录确认共享在响应，再用 `df` 读它的总量、已用和可用。群晖断开后 `df` 可能返回缓存的数字，所以没响应的共享不读。读到的结果和每个共享的挂载位置一起存进系统元数据（`network-share-space`）。网页请求时只读这份记录，不当场读共享，以免群晖没响应时把请求卡住 |
| 记录过期 | 超过 3 分钟没更新（后台服务停了，或检查卡住了），网络共享都按没连上处理 |
| 合计 | 本机：照片库所在的磁盘，当场读取（和原来一样）。网络共享按顺序加进来，以下几种不加：<br>① 手动卸载的；<br>② 没连上的，单独计数并提示；<br>③ 照片库本身就放在这个共享上的，已经算在本机里了；<br>④ 和已经算过的共享在同一个存储卷上的：同一台主机，总量相同，可用空间相差不到 1 GiB（或总量的 0.1%）。例如同一个群晖卷上的 `homes/A` 和 `homes/B`，`df` 报的都是整个卷 |
| 设置 | 管理 → 设置 → 服务器 →“服务器总量包括网络共享”，默认打开。关掉后只算本机，网络共享仍会在详情里列出，标为“不计入”。只在支持网络共享时显示（macOS 原生版）。官方服务器和 Docker 版没有网络共享，行为和原来一样 |
| 用户用量 | 自己上传的照片：和配额一样计算（包括回收站里的）。外部图库的照片：只算还在的，不算回收站里的（离线照片会进回收站），也不算正在删除的图库 |
| `GET /server/storage` | 原有字段的含义改了：<br>· `diskSize`：服务器总量；<br>· `diskUse`：**自己的**用量，上传 + 外部图库；<br>· `diskAvailable`：服务器的可用空间；<br>· `diskUsagePercentage`：自己的用量占服务器总量的比例。<br>新增字段：`usageUploads`、`usageExternal`、`quotaSizeInBytes`、`sharesNotCounted`（没算进去的共享数） |
| `GET /server/storage/details` | 只给管理员：服务器总量、已用、可用，是否包括网络共享，没算进去的共享数，共享容量的读取时间，以及每个存储卷（本机和每个共享）的位置、用量和状态。状态有：已计入、和某某是同一个存储卷、没连上、已卸载、不计入 |
| 网页左下角 | 显示“已用：自己的用量 / 配额或服务器总量”。超过配额时进度条显示为满（设了配额、外部图库又大时会这样）。鼠标悬停显示上传和外部图库各占多少；有配额时说明配额只算上传的；有共享没连上时提示有几个没算进去 |
| 管理后台 → 服务器状态 | 统计信息上方新增“存储空间”：服务器总量进度条（已用 / 总量，可用），本机和每个网络共享各占一行（名称、位置、用量、状态），以及共享容量的读取时间。每 30 秒刷新 |
| 新建、编辑用户时的配额提示 | “超过磁盘大小”的提示原来就读 `diskSizeRaw`，现在比的是服务器总量（包括网络共享），代码没改 |
| 手机 App | 不用改代码。没有配额的用户，App 读 `diskUse` / `diskSize`，看到的就是自己的用量（包括外部图库）/ 服务器总量。有配额的用户，App 读的是用户信息里的 `quotaUsageInBytes`，仍然只算上传的；要和网页一样，需要 App 改成读 `/server/storage` |

## 测试

| 测什么 | 结果 |
|---|---|
| 服务端单元测试：合计（只有本机；加上连上的共享；同一卷的两个共享只算一次，可用空间稍有不同也算同一卷，别的主机上同样大小的卷照算；可用空间不同的两个卷都算；照片库放在共享上时不重复算；没连上的不算并计数，手动卸载的不算；记录过期不用；设置关掉时列出但不计入）；路径判断；每分钟检查记下连上的共享的容量，没响应的不读 `df`；`/server/storage` 的单位换算、自己的用量和配额、按设置算不算共享；管理员详情；新接口只给管理员 | 新增 16 项通过；服务端全部单元测试 2715 项通过，`api-key.controller` 有 1 项偶尔失败（控制器测试的老问题），单独跑两次都过，和这次无关 |
| 数据库测试（真实 Postgres）：用户用量，上传的包括回收站里的；外部图库的不算回收站里的和正在删除的图库；别的用户的照片不算；没有照片时是 0 | 新增 2 项通过 |
| 网页：左下角，没有配额时是服务器总量、有配额时是配额，超过配额显示为满，悬停说明，共享没连上的提示；管理后台的存储空间详情：各卷的状态、没算进去的提示、关掉设置时的提示 | 新增 5 项通过 |
| 类型检查、lint、格式 | 通过。网页 eslint 的 `tscompat` 规则照旧关掉；svelte-check 的 7 个错误是原来就有的 |

`e2e` 里 `/server/storage` 的期望值和网页模拟数据补上了新字段，但这台机器上没装 e2e 的依赖，没有跑。

## 还没做的

- 正式服上核对：
  - 同一个群晖卷上的两个共享，`df` 报的是不是整个卷（总量相同、可用相近），管理后台里有没有标为同一个存储卷；如果群晖给共享文件夹设了配额，`df` 报的会是配额，这时就按不同的卷各算一次；
  - 拔掉群晖的网线，1 分钟内共享显示“没连上”，总量减掉它，左下角提示有几个没算进去；恢复后加回来；
  - 普通用户左下角的用量 = 管理后台“用户用量”里他那一行（打开“统计包括外部图库”时）。
- 手机 App 里设了配额的用户，要改成读 `/server/storage`，才能和网页一样包括外部图库。
