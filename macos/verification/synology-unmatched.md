# 群晖照片相册同步：对不上的照片和相册列出来

- 分支：`mac/feat/synology-albums`
- 日期：2026-11-04
- 结论：每次同步把对不上的相册和照片完整记下来，不再只留前 20 张的路径：没找到的照片、按名字对上多张的照片、主人还不在 Immich 里的照片、没建的相册、群晖没列出照片的相册。账号设置 → 群晖照片 → 上次同步里可以按相册查看，也可以下载成 CSV。另外补上方案里约定、上一步没做的一条：自己的照片按路径找不到时，再按文件名 + 大小 + 时间在自己的全部照片里找（例如手机上传的）。服务器单元测试新增 3 项（群晖相关共 135 项）、数据库测试新增 2 项（共 17 项）、网页新增 2 项（共 15 项）通过。用真实账号在正式服上同步还没做，见文末

## 怎么做的

| 部分 | 做法 |
|---|---|
| 自己的照片：按名字找 | 按路径在外部图库里没找到，或文件夹读不到时，在自己的全部照片里（包括上传的；不含回收站、锁定文件夹和实况照片的视频部分）按文件名（NFC、不分大小写）+ 大小 + 时间（差 1 秒以内）找，规则和别人的照片一样。群晖没给大小或时间的照片不按名字找，只有名字不够 |
| 对上多张 | 自己的和别人的照片都一样：依次用已在相册里的、在线的、外部图库的、路径最短的那张，计数，也列进清单 |
| 记什么 | 新表 `synology_unmatched`，每行一项：群晖相册 ID 和名字、原因、照片的群晖路径（文件夹读不到时只有文件名）、是不是自己的照片。原因有五种：没找到、对上多张、主人还不在 Immich 里、相册没建（一张照片都没找到）、群晖没列出这个相册的照片 |
| 不写谁 | 别人的照片只标“别人加的”，不写是谁；主人还不在 Immich 里的也一样，和报告里只写人数一致 |
| 什么时候换 | 每次同步结束时，和报告一起整份替换。同步失败（登录不上、群晖列不出相册）时清空，因为报告也换成了失败；解除绑定时清空；删用户时跟着删 |
| 报告 | 去掉原来的“前 20 张没找到的照片路径”，改为清单的条数；多两项：按名字找到的自己的照片数、对上多张的照片数（原来只算别人的，现在两种都算） |
| 接口 | `GET /synology/account/unmatched`，返回清单，按相册名和路径排序。上次同步不成功时返回空 |
| 网页 | 上次同步下面一行“没对上的相册和照片：N 项”，旁边“查看列表”和“下载列表”。列表按相册分组，相册没建或读不到时在相册名下面写原因，照片后面写原因、是不是别人加的；最多显示 500 张，全部要下载看。CSV 四列：相册、原因、谁的、照片路径；带 BOM，表格软件按 UTF-8 打开，开头是 `=`、`+`、`-`、`@` 的格子前面加 `'`，不会被当成公式。每次同步后重新读 |
| 数据库 | 新表并进这一组还没发布的迁移（`1793750400000-AddSynologyAlbums`），升级时一共建四张表 |

## 测试

| 测什么 | 结果 |
|---|---|
| 服务端单元测试：读清单（有成功的同步才返回）；同步登录失败时清空；解除绑定时清空；新接口要登录 | 新增 3 项，群晖相关共 135 项通过 |
| 服务端全部单元测试 | 2845 项通过 |
| 数据库测试（真实 Postgres）：自己的照片按路径没找到、按名字 + 大小 + 时间在上传的照片里找到，没给大小和时间的不按名字找；清单里有没找到的（自己的、带路径）、主人不在 Immich 里的（别人的、只有文件名）、没建的相册、读不到的相册，条数和报告一致；下次同步整份替换，同步失败后为空；删用户时跟着删 | 新增 2 项，共 17 项通过 |
| 网页：报告里显示按名字找到的数量和清单条数；打开列表才去读、按相册分组、写原因和“别人加的”，收起后不重读；下载的 CSV 内容（含逗号、引号和 `=` 开头的相册名） | 新增 2 项，共 15 项通过 |
| 迁移：在空数据库上从头跑一遍、和表定义比对（`sql-tools migrations generate` 显示没有差异）、回退后群晖的四张表都删掉 | 通过 |
| 类型检查、lint、格式 | 通过。网页 eslint 的 `tscompat` 规则照旧关掉；svelte-check 的 7 个错误是原来就有的 |

数据库测试照旧用本机临时起的 Postgres（带 VectorChord），测试配置是临时的，没有提交。
