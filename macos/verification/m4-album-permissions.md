# M4-6：共享相册权限（下载、管理者）

- 分支：`mac/develop`
- 日期：2026-11-03
- 状态：**通过**（v3.3.5-mac.6）
- 结论：共享相册的成员从"查看者 / 编辑者"两档变成五档：仅查看、可下载、可编辑、可管理、所有者。新加的查看者默认只能看、不能下载原图；编辑者只能加、移照片；邀请、移除成员、改权限、改相册名和描述、选封面、建共享链接只有管理者和所有者能做；删除相册只有所有者能做。已有相册保持原来能做的事。

## 规则（用户确认）

| 档 | 看照片 | 下载原图 | 加照片、移除自己的照片 | 管理（成员、名称描述封面、共享链接、移除任何照片、删别人的评论） | 删除相册 |
|---|---|---|---|---|---|
| 仅查看 | ✓ | | | | |
| 可下载 | ✓ | ✓ | | | |
| 可编辑 | ✓ | ✓ | ✓ | | |
| 可管理 | ✓ | ✓ | ✓ | ✓（不能移除所有者） | |
| 所有者 | ✓ | ✓ | ✓ | ✓ | ✓ |

- 对应群晖照片的查看者、下载者、上传者、管理者。没有做"只能移除自己加的照片"以外的细分。
- 成员总能下载自己的照片。
- 已有相册：升级时原来的查看者变成"可下载"（原来就能下载），原来的编辑者变成"可管理"（原来就能改相册名、描述和封面，现在这些归管理者）。新加的成员按新规则。

## 实现

- 数据：`album_user` 新增 `allowDownload`、`isManager` 两列（默认 `false`）。迁移 `1793577600000-AddAlbumUserAccess` 加列，并把已有成员设为 `allowDownload = true`、编辑者 `isManager = true`。
- 接口：角色仍是 `owner / editor / viewer` 三种，官方手机 App 严格解析这个枚举，不能加新值。"可下载"是 `viewer` + `allowDownload`，"可管理"是 `editor` + `isManager`。
  - 添加成员（`POST /albums`、`PUT /albums/:id/users`）和改权限（`PUT /albums/:id/user/:userId`）可以带 `allowDownload`、`isManager`。
  - 不带时：改的是同一个角色，就保留原值（手机 App 只发 `role`，不会把"可下载"改回"仅查看"）；换了角色，就用默认值。
  - 编辑者、所有者的 `allowDownload` 总是 `true`；`isManager` 只对编辑者有效。
  - 不能把成员加成或改成所有者。
  - 返回的 `albumUsers` 带上这两个字段。
- 权限（`utils/access.ts`，`AccessRepository.album.checkSharedAlbumAccess(..., 'view' | 'download' | 'edit' | 'manage')`）：

  | 权限 | 原来 | 现在 |
  |---|---|---|
  | `album.read` | 成员 | 成员 |
  | `album.download` | 成员 | 所有者、可下载及以上 |
  | `asset.download`（原图、打包下载） | 能看到就能下载 | 自己的、伙伴的，或在一个自己可下载的相册里 |
  | `albumAsset.create`、`albumAsset.delete` | 编辑者 | 编辑者（含管理者） |
  | `album.update`（名称、描述、封面、排序、评论开关） | 编辑者 | 管理者 |
  | 移除别人加的照片（`canAlwaysRemove`） | 所有者（`album.delete`） | 管理者（`album.update`） |
  | `album.share`（邀请、移除成员、改权限、共享链接） | 编辑者 | 管理者 |
  | 删除别人的评论 | 所有者 | 所有者、管理者 |
  | 移除所有者（有多个所有者时） | 编辑者 | 只有所有者（`album.delete`） |

- 全尺寸图：网页支持的格式（JPEG 等）看全尺寸时原来直接跳到原图；现在只有能下载原图的人才跳，其他人跳到全尺寸图或预览图。
- 网页：
  - 选项弹窗的成员权限下拉改为"可管理 / 可编辑 / 可下载 / 仅查看 / 所有者 / 移除用户"，上方加一行说明。
  - 按权限显示按钮：
    - 只有管理者和所有者能看到分享、添加用户、共享链接、编辑名称和描述、选封面，选项弹窗也只对他们可编辑；
    - 只有能下载的人能看到下载相册，以及查看器里的下载、下载原图；
    - 移除照片：管理者能移除任何照片，编辑者只能移除自己的。
  - 在不能下载的相册里，查看器不加载原图（"总是加载原图"、动态照片悬停播放、"播放原始视频"都改用全尺寸图、预览图或转码视频），否则会请求失败。

## 实测中修正的问题

- `AlbumRepository.create` 用 `unnest` 一次插入多个成员：
  - 传布尔数组时，postgres.js 把它当成一个布尔值发送，建相册直接 500；
  - 改传字符串数组并写成 `::boolean[]`，又全部变成 `false`；
  - 最终用 `unnest($n::text[]::boolean[])`，先当文本数组再转换。
  - 单元测试用的是 mock，发现不了这个问题，是端到端测试和查询检查发现的。

## 已知限制

- 官方手机 App 不认识新增的两个字段：
  - 它显示的仍是"查看者 / 编辑者"；
  - 在 App 里改角色只发 `role`：同一角色保留原设置，换角色时用默认值（新的查看者不能下载，新的编辑者不是管理者）；
  - App 里的下载、全尺寸原图对不能下载的查看者会失败，服务端会拒绝。
- 不能下载的查看者仍能播放视频：不需要转码的视频播放的就是原文件，只是网页上没有下载按钮。截图和复制当前显示的图片也挡不住。
- 照片详情里的"分享"（给单张照片建共享链接）对所有相册成员都显示，但只有照片所有者和伙伴能建成功，这是上游的现状。
