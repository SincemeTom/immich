# RAW 照片的预览默认用相机内嵌的 JPG

- 日期：2026-10-30
- 分支：`mac/feat/raw-embedded-preview`
- 结论：**通过**。"管理 → 设置 → 图像 → 优先使用嵌入式预览"（`image.extractEmbedded`）改为默认打开，RAW 照片在 Immich 里的样子和相机直出的 JPG 一致。升级时只把 RAW 照片的预览重新生成一次，其他照片不动；以后在网页上切换这个开关，也会自动重新生成 RAW 的预览，不用再手动跑"缩略图 → 全部"。端到端 11/11 通过，服务端单测全部通过

## 问题

上游默认用 libvips/LibRaw 解码 RAW 数据来做预览和缩略图。这是"中性"的解码：不带相机的色彩风格、动态范围优化、镜头校正，所以和相机 JPG 看起来不一样（常见的是偏暗、偏灰）。上游有"优先使用嵌入式预览"这个开关，但默认关闭；打开后还要自己到任务队列里对缩略图点"全部"，这会把**所有**照片的缩略图重做一遍。

Sony A7C II 的每个 ARW 里都内嵌了一张 7008×4672 的全尺寸 JPG（`JpgFromRaw`），就是相机直出那张。Immich 用内嵌预览的条件是短边不小于预览尺寸（1440），满足；内嵌图太小的相机（老机型只嵌 1616×1080 之类）会自动退回解码 RAW。

## 改动

| 位置 | 改动 |
|---|---|
| 默认配置 | `image.extractEmbedded` 改为 `true`（`config.dto.ts`、文档 `config-file.md`） |
| 记录 | 新增 `system_metadata` 键 `raw-previews`，记下现有 RAW 预览是按哪种方式生成的 |
| 自动重做 | 后台进程启动时、设置改变时比对：和记录不一致就只给 RAW 照片（按扩展名，30 多种格式）排队重新生成缩略图，然后更新记录。数据库锁保证多个进程只做一次 |
| 升级 | 没有记录时，按保存的设置判断（没保存过就是上游默认的"关"）：所以从上游或之前版本升级过来，RAW 预览会重做一次；原来已经手动打开过的，不重做 |
| 配置缓存 | 排队前先清掉本进程的配置缓存。第一次测试发现任务比"清缓存"的事件处理先开始执行，读到的还是旧设置，结果生成的和原来一模一样 |

如果你确实想要中性解码的效果，到设置里关掉这个开关保存即可，RAW 的预览会自动按解码方式重做。

## 端到端（`macos/scripts/m1_raw_preview.py`）

隔离测试实例（`local.immich-p6`），上传这台 Mac 上 3 对真实的 A7C II ARW+JPG（CAM00074、76、88）。比较 RAW 的预览和对应 JPG 的预览：缩到同样大小后每个像素的平均差（0–255），以及平均亮度差。

| 照片 | 内嵌 JPG（默认） | 解码 RAW（上游默认） |
|---|---|---|
| CAM00074 | 像素差 0.1，亮度差 0.1 | 1.0 / 0.1 |
| CAM00076 | 0.4 / 0.1 | 7.8 / 1.9 |
| CAM00088 | 0.4 / 0.1 | 11.6 / **10.8** |

| 场景 | 结果 |
|---|---|
| 新安装，默认 | 通过：设置为打开；RAW 预览和相机 JPG 几乎一样 |
| 关闭开关 | 通过：3 张 RAW 的预览重做（解码），JPG 的预览不动 |
| 再打开 | 通过：RAW 预览重做，和最初一致 |
| 改别的图像设置（预览质量） | 通过：预览不动 |
| 模拟升级（预览是解码生成的、没有记录、设置是上游默认） → 重启服务 | 通过：启动时只重做 RAW 的预览，变为内嵌 JPG；记录写入；再次重启不再重做 |
