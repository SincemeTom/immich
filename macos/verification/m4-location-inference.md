# M4-5：没有位置的照片按附近时间拍的照片推断位置

- 分支：`mac/develop`
- 日期：2026-11-03
- 状态：**通过**（v3.3.5-mac.6 首版；规则调整见"规则调整（mac.7）"）
- 结论：没有 GPS 的照片（相机、截图以外的大部分非手机照片，关了定位的手机照片），用附近时间拍的、有位置的照片的位置，并标记为"推断"。有两种情况：夹在同一地点的两张之间（每边最多 3 小时），或者离最近的一张不超过 30 分钟。先只用自己的照片，推断不出来时，再用同一个共享相册里别人的照片。只写数据库，不改原文件和 xmp；地图、地点搜索、中文地名都能用；详情面板显示推断依据；本人可以单张清除，清除后不再推断；管理员可以调规则、关掉或一键清除全部。

## 规则（用户确认）

| 项 | 选择 |
|---|---|
| 夹在中间 | 前、后各找最近一张有位置的照片，都在 **3 小时**内、且两张相距 ≤ **1 公里**：取时间更近的一张（一样近取前一张） |
| 紧挨着 | 不满足上一条时（只有一侧有，或两张相距较远，或有一边超过 3 小时），最近那张在 **30 分钟**内就用它的位置 |
| 其他 | 不推断。宁可不推断，也不推断错 |
| 来源 | 先只用本人的照片；推断不出来时，再加上**和这张照片在同一个相册里**的别人的照片（一起旅行时对方手机有 GPS）。已推断的不作为来源，回收站里的不算，相册在回收站里也不算 |
| 可调 | 管理 → 设置 → 元数据：紧挨着（分钟，默认 30）、夹在中间（分钟，默认 180）、同一地点的距离（米，默认 1000）。改了以后自动全部重算 |
| 保存 | 写入 `asset_exif` 的经纬度和城市、省、国家，`locationInferred = true`，`locationInferredFromId` 记来源照片；不写原文件、不写 xmp |
| 网页 | 详情面板地点下显示"推断"，下面写依据："根据 10:00 拍的照片"，别人的照片写"根据 某某 10:00 拍的照片"，不是同一天时带上日期；本人可以点 × 清除；管理 → 设置 → 元数据 有开关、三个数和"清除推断的位置"；管理 → 任务 有"位置推断"队列，可补跑 |

## 规则调整（mac.7）

用户反馈"前后都要有、各 1 小时"太苛刻，共享照片的位置也有点怪。正式库里的例子：584954237@qq.com 的 10-29 06:00–06:30 有 32 张索尼 A7C II 的照片没有位置，之前只有 05:40 和 05:50 两张 iPhone 照片（梅陇镇），之后没有，卡在"前后都要有"。按新规则，06:00–06:09 的 28 张用 05:50 那张的位置（都在 20 分钟内），06:30 的 4 张（离 05:50 已 40 分钟）不推断。

共享照片原来的规则是：你所在的任何相册里，别人的照片都可以给你所有照片推断位置，甚至不在同一个相册里的照片之间也会互相影响。现在只在同一个相册里，而且只在自己的照片推断不出来时才用。

## 实现

- 数据：`asset_exif.locationInferred`（`true` 推断的；`false` 本人清除过，不再推断；`null` 都不是），`asset_exif.locationInferredFromId`（来源照片）。迁移 `1793491200000-AddLocationInferred` 加第一列和 `asset("localDateTime")` 索引（查前后照片用），`1793664000000-AddLocationInferredFrom` 加第二列。
- 规则：`utils/location-inference.ts` 的 `inferLocation(time, before, after, rules)`，返回坐标和来源照片 id。查前后照片的范围是两个时间里较长的一个（`locationInferenceWindowMs`）。
- 时间按 **当地时间**（`asset.localDateTime`）比较，不按 UTC：有 GPS 的照片服务端按坐标定时区（上海 10:00 存为 UTC 02:00），没有 GPS 的相机照片通常也没有时区，10:05 被当成 UTC 10:05，按 UTC 比差 8 小时，一张也推断不出来。
- 触发（`LocationInferenceService`，队列 `locationInference`，并发 2）：
  - 每张照片元数据提取完（`AssetMetadataExtracted`）：没有位置的，推断自己；有位置的，把范围内能用它推断的照片（本人的，和同一相册里的）排进队列。所以先传了没位置的、后传有位置的也能推断上。
  - 照片加入相册（`addAssets`、`addAssetsToAlbums`）：同上。
  - 照片移出相册（`removeAssets`）：移出的照片，和以它为来源推断的照片（`getInferredFrom`）重新推断，不再能用的就撤掉。
  - 第一次开启（包括升级）时，对全部没有位置的照片跑一遍；关了再开也会再跑。规则和上次推断时的不同（包括从只有开关的版本升级上来）时，连已推断的也全部重算。状态和规则记在 `system_metadata` 的 `location-inference`。
  - 管理 → 任务 → 位置推断："缺失"跑没有位置的；"全部"连已推断的也重算（来源被删、被移走后，原推断会撤掉）。
- 优先级：照片自己的位置（文件里的、手动设置的）总是优先。重新提取元数据时，文件里没有位置就保留推断的，有就覆盖并去掉标记；手动设置位置会去掉标记（`AssetService.update`、`updateAll`）。
- 接口：
  - `GET /api/inferred-locations/:id`（`asset.read`）：推断依据 `{ source: { assetId, localDateTime, ownerId, ownerName } | null }`。来源照片当前用户看不到时 `assetId` 为 null，只给时间和主人名字；
  - `DELETE /api/inferred-locations/:id`（本人，`asset.update`，清除后不再推断）；
  - `DELETE /api/admin/inferred-locations`（管理员，清除全部，可以再推断）；
  - 资产详情的 `exifInfo.locationInferred` 为 `true` 时表示推断的。
- 配置：`metadata.locationInference`：`enabled`（默认开）、`nearbyMinutes`（0–1440，默认 30）、`betweenMinutes`（0–1440，默认 180）、`maxDistanceMeters`（0–100000，默认 1000）；`job.locationInference.concurrency`，默认 2。

## 已知限制

- 跨时区旅行时，当地时间相同的照片可能实际相差几小时。"夹在中间"还要求两张相距 1 公里以内，推断错的可能很小；"紧挨着"只有 30 分钟，也不大。
- 一组没有位置的照片在一张有位置的照片之后连续拍了很久（超过 30 分钟），之后又没有有位置的照片，超过 30 分钟的部分不推断。可以在设置里调大"紧挨着"的分钟数。
- 退出共享相册、或相册被删除后，用其中别人照片推断的位置不会立即撤掉，按"全部"补跑或改一次规则才会重算。照片移出相册会立即处理。
- 通过共享链接查看时不显示推断依据（这个接口只给登录用户）。
