# M4-5：没有位置的照片按前后拍的照片推断位置

- 分支：`mac/develop`
- 日期：2026-11-03
- 状态：**通过**（v3.3.5-mac.6）
- 结论：没有 GPS 的照片（相机、截图以外的大部分非手机照片，关了定位的手机照片），如果前后 1 小时内各有一张有位置的照片、且这两张相距不超过 1 公里，就用时间更近的那张的位置，并标记为"推断"。只写数据库，不改原文件和 xmp；地图、地点搜索、中文地名都能用；本人可以单张清除，清除后不再推断；管理员可以关掉或一键清除全部。

## 规则（用户确认）

| 项 | 选择 |
|---|---|
| 推断规则 | 前后夹击：前、后各找最近一张有位置的照片，都在 1 小时内、且相距 ≤ 1 公里才推断，取时间更近的一张（一样近取前一张）。宁可不推断，也不推断错 |
| 保存 | 写入 `asset_exif` 的经纬度和城市、省、国家，`locationInferred = true`；不写原文件、不写 xmp |
| 来源 | 本人的照片，加上本人所在相册里别人的照片（一起旅行时对方手机有 GPS）。已推断的不作为来源，回收站里的不算，相册在回收站里也不算 |
| 网页 | 详情面板地点下显示"推断"，本人可以点 × 清除；管理 → 设置 → 元数据 有开关和"清除推断的位置"；管理 → 任务 有"位置推断"队列，可补跑 |

## 实现

- 数据：`asset_exif.locationInferred`（`true` 推断的；`false` 本人清除过，不再推断；`null` 都不是）。迁移 `1793491200000-AddLocationInferred` 加这一列和 `asset("localDateTime")` 索引（查前后照片用）。
- 时间按 **当地时间**（`asset.localDateTime`）比较，不按 UTC：有 GPS 的照片服务端按坐标定时区（上海 10:00 存为 UTC 02:00），没有 GPS 的相机照片通常也没有时区，10:05 被当成 UTC 10:05，按 UTC 比差 8 小时，一张也推断不出来。端到端第一次就是这样失败的，改成当地时间后通过。
- 触发（`LocationInferenceService`，队列 `locationInference`，并发 2）：
  - 每张照片元数据提取完（`AssetMetadataExtracted`）：没有位置的，推断自己；有位置的，把前后 1 小时内能用它推断的照片（本人的，和它所在相册里各成员的）排进队列。所以先传了没位置的、后传有位置的也能推断上。
  - 照片加入相册（`addAssets`、`addAssetsToAlbums`）：同上，相册成员前后的照片可能因此有了来源。
  - 第一次开启（包括升级到这个版本）时，对全部没有位置的照片跑一遍；关了再开也会再跑。状态记在 `system_metadata` 的 `location-inference`。
  - 管理 → 任务 → 位置推断："缺失"跑没有位置的；"全部"连已推断的也重算（来源被删、被移走后，原推断会撤掉）。
- 优先级：照片自己的位置（文件里的、手动设置的）总是优先。重新提取元数据时，文件里没有位置就保留推断的，有就覆盖并去掉标记；手动设置位置会去掉标记（`AssetService.update`、`updateAll`）。
- 接口：`DELETE /api/inferred-locations/:id`（本人，`asset.update` 权限，清除后不再推断）；`DELETE /api/admin/inferred-locations`（管理员，清除全部，可以再推断）。资产详情的 `exifInfo.locationInferred` 为 `true` 时表示推断的。
- 配置：`metadata.locationInference.enabled`，默认开；`job.locationInference.concurrency`，默认 2。

## 已知限制

- 前后两张都要有位置。一天里只有一张有位置、或者没位置的照片在一组照片的最前或最后，不推断。
- 跨时区旅行时，当地时间相同的照片可能实际相差几小时；但前后两张还得相距 1 公里以内，推断错的可能很小。
- 共享相册里别人的照片只在本人还在这个相册里时作为来源。退出相册后，已推断的位置不会自动撤掉，按"全部"补跑才会重算。
