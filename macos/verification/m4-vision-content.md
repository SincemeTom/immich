## 怎么做的

| 部分 | 内容 |
|---|---|
| `macos/vision/immich-vision.swift` | 常驻的小程序：每行读一个任务（预览图路径 + 要做的请求），每行写一个结果。用 Vision 的分类（1303 个标签）、美学分、动物（猫狗）、条码四个请求。模型是系统的，安装包只多一个约 140 KB 的程序 |
| 服务端 `VisionRepository` | 有照片要分析时启动它，按任务 id 对应结果；单张 60 秒超时、程序退出时让等待中的任务失败并在下一张时重启；空闲 5 分钟后停掉 |
| 新任务队列"内容分析" | 缩略图生成之后排队（和智能搜索、人脸、OCR 并列），并发 2。任务页面有"缺失""全部"按钮；分析结果存新表 `asset_vision`（不改上游已有的表），带版本号，以后改规则时版本加一即可只重做旧的 |
| 标签 | `server/src/utils/vision-labels.ts`：1303 个标签逐个译成中文路径，分 14 类（动物、植物、食物、饮品、物品、交通、建筑、场所、风景、人物、活动、运动、文档、艺术）；太宽泛的 84 个不用（结构、户外、天空、加工木材、家具……）。置信度 ≥ 0.5，只留最具体的一级（有"动物/猫"就不再单独打"动物"），每张最多 5 个，写成 Immich 自带的标签，前缀"自动/"。用户自己的标签、文件里的标签不受影响；重新提取元数据时自动标签保留 |
| 截图 | 文件名是截图（Screenshot、截屏、屏幕截图……），或者没有相机信息且是 PNG、正好是屏幕分辨率（iPhone、安卓、iPad、Mac 和常见显示器共 60 种）、分类为 screenshot。标签"自动/截图"；视频不算 |
| 二维码 | 标签"自动/文档/二维码"，内容存在 `asset_vision.barcodes` |
| 截图归档 | 设置里的开关，**默认关闭**。打开后只在第一次分析时归档，从归档里移出的不会再被归档 |
| 网页设置 | 管理 → 设置 → 机器学习 → 内容分析（Apple Vision）：启用、自动标签、截图自动归档；任务设置里可调并发数 |
| 没有这个程序时 | Docker、Linux，或 `install.sh` 所在的 Mac 编译不了 Swift：任务直接跳过，其他功能不受影响 |

打包：`build-release.sh` 编译它（目标 macOS 15）放进 `build/vision/`，`build-pkg.sh` 和其他程序一起签名、公证；`install.sh` 在源码更新时重新编译，编译失败只关掉这个功能。`bundle_dylibs.py` 原来把所有绝对路径的 rpath 当问题，Swift 程序带的 `/usr/lib/swift` 是系统自己的，改为接受。

## 这台 Mac 的真实照片（只读预览）

用发布版的程序和服务端自己的标签代码跑了这台 Mac 库里的 85 张（iPhone 16、索尼相机、大疆无人机，含视频的预览图），没有写入数据库：

- 每张中位数 38 ms（4 个请求）；5 万张约 30 分钟，M4 估计 40–45 分钟
- 64 张有标签，21 张没有（夜景、模糊、构图杂的）；截图 0、二维码 0（库里确实没有）
- 最常见：餐具/盘子 17、场所/道路 13、交通/汽车 10、风景/夜空 10、建筑/拱门 8、人物 7、食物/蔬菜/西兰花 6、物品/路灯 6
- 据此改了三处：道路和街道原来总是成对出现，合成一个"场所/道路"；"手表"放到"钟表"下面，不再两个都打（一张晚餐照片被认成手表，0.74，Vision 本身的误判）；"家具"太宽泛，桌上的照片几乎都有，去掉

## 已知的限制

- 标签只有 Vision 的 1303 个固定词，"鹅""山谷"这类没有；准确度见调研第 3 节（按标签找第一名 50%，智能搜索 90%），所以它用来按类浏览，不代替智能搜索
- 签名后的程序（hardened runtime）这次只在未签名的发布目录上测过；签名、公证要等下一个正式包，打包检查的 `--signed` 会检查它的签名

### 视频语音识别（macOS 26）

- 用 AVFoundation 读出视频的第一条音轨，转成 16 kHz 单声道（每分钟约 2 MB，临时文件，用完即删）；再交给 `SpeechAnalyzer` + `SpeechTranscriber` 按设置的语言转写。语言模型第一次使用时由 macOS 下载、之后一直留在系统里
- 结果存 `asset_vision`：`transcriptSegments`（每段的起止时间和原文）、`transcriptLanguage`；`transcript` 是给搜索用的文字，和 OCR 一样分词（中文按相邻两字），建 trigram 索引
- **搜索**：网页上"按照片中的文字搜索"（OCR 那个搜索项）同时搜视频里说的话。实测分词后的存储与查询：搜"宝宝""生日快乐""宝宝的生日""birthday"都能命中，"圣诞"不会误中
- 单个视频最多 30 分钟；转写失败（如离线下载不了模型）不影响这张的其他分析，下次"缺失"时重试；关掉语音识别时已有的文字保留
- 程序里的任务改为并发执行，一段长视频转写时照片照常分析

### 文档、镜头脏污（macOS 26）

- 文档打"自动/文档"，有表格的打"自动/文档/表格"；镜头脏污打"自动/质量/镜头脏污"（宁可漏标，不冤枉照片）；分数都存下来
- 判断规则最初是按调研的设想定的，已在 macOS 27.2 上用真实照片校准，见下文 2.4

### 2.4 macOS 26–27 实测与校准（2026-11-02，macOS 27.2，SDK 26.2）

`capabilities` 返回 classify、aesthetics、animals、barcodes、documents、smudge、speech 七项。

**语音**：6 分钟的大疆普通话视频转写用了 4.9 秒，分段和文字正确；合成的"生日快乐"视频能转写出全文。

**文档**：`RecognizeDocumentsRequest` 对**任何**图片都返回 1 个文档，`confidence` 恒为 0，区域是整张图。原规则要求把握 ≥ 0.8，因此永远不会打标签。程序改为额外报告读到的字数（`characters`）和文字行框占画面的比例（`textArea`），`HELPER_VERSION` 升到 3。实测：

| 图片 | 字数 | 文字占比 | 表格 | 分类器 | 应该 |
|---|---|---|---|---|---|
| 书页（book-beside-flowers） | 628 | 0.94 | 0 | — | 是 |
| 电费通知单（合成，含表格） | 502 | 0.13 | 1 | — | 是（表格） |
| 手写笔记（handwritten-notes） | 329 | 0.15 | 0 | handwriting 0.49 | 是 |
| 粉笔菜单板 | 406 | 0.13 | 0 | chalkboard 0.31 | 否 |
| 啤酒馆招牌（craft-beer） | — | 0.13 | 0 | — | 否 |
| 街景路牌 | 84 | 0.01 | 0 | sign 0.17 | 否 |
| 墙上的发光店名 | 5 | 0.27 | 0 | — | 否 |

新规则（`server/src/utils/content-analysis.ts` 的 `isDocument`）：有表格且 ≥ 20 字；或 ≥ 100 字且文字占比 ≥ 0.3（整页文字）；或 ≥ 100 字、占比 ≥ 0.05，且分类器以 ≥ 0.3 的把握看到 document / printed_page / handwriting / receipt。

**镜头脏污**：人工加脏（局部高斯模糊加灰雾，三档）的图大多 ≥ 0.99，原图都很低，说明检测本身有效。但按原阈值 0.9，误报有：两张白墙（0.996，分类器看不到任何东西）、背景虚化的仓鼠（0.986）、一张布料特写（0.928）。新规则（`isSmudged`）：≥ 0.99，**且**分类器以 ≥ 0.3 的把握看到某样东西。白墙因为分类器看不到东西被排除，虚化背景因为分数低于 0.99 被排除。

本机照片库和 e2e 测试素材全部重跑一遍：文档只标出书页、通知单、手写笔记；镜头脏污只标出人工加脏的图。

### 美学分选自动堆叠的封面（这台 Mac 上就能用）

- 堆叠里照片的排序：编辑版 > 非 RAW > 收藏 > 评分 > **美学分高** > 像素多 > 拍得早。原来的规则不变，美学分只在它们都一样时起作用（连拍、相似照片）
- 一张照片分析完时，如果它在自动堆叠里，重新比较一次：比现在的封面好（按规则更好，或规则相同而美学分高至少 0.05）才换，避免相近的照片来回换。你自己选过封面的堆叠不是"自动"的了，不会动

### 为什么人物头像这次没做

上游没有记录人物头像是自动选的还是你手动选的（都写在 `person.faceAssetId`），自动替换可能覆盖你选的头像；而且人脸识别和内容分析是并行的，分析时人脸常常还没出来。要做得加一个记录"头像是谁选的"的字段，改动上游的人物流程，留到以后单独做。
