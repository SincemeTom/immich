# 问题 2：自动堆叠

- 日期：2026-10-30
- 分支：`mac/feat/auto-stack`
- 结论：**通过**。每个用户在"账户设置 → 自动堆叠"里自己开启，并选择堆叠哪几类：连拍、RAW+JPG、编辑版、相似照片，相似照片还能设置相似度和拍摄间隔。每次上传和外部库扫描后在后台自动执行；管理员在"任务队列"里可以对所有开启了的用户统一执行。用真实照片跑端到端 25/25 通过，服务端单测 2487 项、网页单测 560 项全部通过

## 设计

| 问题 | 做法 | 原因 |
|---|---|---|
| 谁来设置 | **每个用户自己设置**（账户设置），管理员只管任务队列 | 堆叠是个人的整理习惯，规则因人而异；人脸识别那种全局开关不适合 |
| 什么时候执行 | 每张新照片处理完（元数据、缩略图、智能搜索向量都有了）后自动执行；保存设置时整理一遍现有照片；管理员可在任务队列里执行"缺失 / 全部" | 和人脸识别、重复检测一样走后台队列；队列并发为 1，同时到达的 RAW 和 JPG 不会互相抢 |
| 封面 | 编辑版优先 → JPG/HEIC 优先于 RAW → 收藏 → 评分高 → 像素多 → 拍得早 | 时间线上显示的应该是"成片"：相机出的 JPG、编辑后的版本 |
| 安全 | **只会往堆叠里加照片**：不删除照片，不把照片移出堆叠，不合并两个已有堆叠；手动建的堆叠只会被加入照片，封面不会被改；用户从自动堆叠里移出的照片会记住，以后不再放回去 | 堆叠是可以撤销的整理操作，但自动化必须尊重人工的决定 |
| 撤销 | "移除所有自动堆叠"：只删自动生成的堆叠（新增 `stack.isAutomatic` 字段区分），照片和手动堆叠都不动；"重新堆叠"：移除后按新设置重新整理 | 调整相似度时可以反复尝试，不用一个个手动拆 |

### 四条规则

| 规则 | 判断依据 | 默认 |
|---|---|---|
| 连拍 | 相机或手机写入的连拍 ID 相同（`BurstUUID` iPhone、`BurstID` Google 相机等，Immich 原来就会读取并保存，但从来没用过） | 开 |
| RAW + JPG | 文件名相同（不区分大小写）、一个是 RAW 一个不是；并且在同一个文件夹，或者（上传到不同目录时）拍摄时间相差不到 1 秒、相机型号相同 | 开 |
| 编辑版 | `IMG_E1234` ↔ `IMG_1234`（iPhone）、`IMG_1234-edited` ↔ `IMG_1234`（Google 相册导出）、`IMG_1234 (edited)`；照片配照片、视频配视频；同样要求同文件夹或同一时刻 | 开 |
| 相似照片 | 智能搜索（CLIP）向量距离 ≤ 阈值，**并且**拍摄时间相差 ≤ N 秒 | 关；开启后默认 0.02 / 10 秒 |

### 为什么相似照片必须加时间窗口

用这台 Mac 上的真实照片算了一遍 CLIP 距离：

| 照片 | 距离 | 间隔 | 实际 |
|---|---|---|---|
| IMG_5572 / IMG_5573 | 0.011 | 1.4 秒 | 同一场景连按 |
| IMG_5571 / IMG_5573 | 0.014 | 4 秒 | 同一场景连按 |
| CAM00074 的 ARW / JPG | 0.013 | 0 | **同一张照片** |
| CAM00087 的 ARW / JPG | 0.034 | 0 | **同一张照片** |
| CAM00082 / CAM00088 | 0.034 | 26 分钟 | 两张不同的照片 |
| IMG_5562 / IMG_5561 | 0.059 | 2 秒 | 同一时刻 |

同一张照片的 RAW 和 JPG 距离可能比 26 分钟后拍的另一张还大，所以单看相似度既会漏掉也会误堆。加上"几秒内"的限制后，0.02 / 10 秒只会堆叠真正连着拍的照片。界面上提供三档：严格 0.01、推荐 0.02、宽松 0.03。

## 实现

| 部分 | 内容 |
|---|---|
| 数据库 | 迁移 `1793318400000-AddAutoStack`：`asset_job_status.autoStackedAt`（照片被自动堆叠的时间：之后它不在堆叠里，说明是被人移出来的），`stack.isAutomatic`。用 `sql-tools` 对比过，迁移和表定义一致 |
| 个人偏好 | `autoStack { enabled, burst, rawJpeg, edited, similar, maxDistance, maxSeconds }`，存在原有的用户偏好里 |
| 队列 | 新队列 `autoStack`（并发 1）：`AssetAutoStackQueueAll`（全部用户，或单个用户）、`AssetAutoStack`（单张照片）。新照片的智能搜索任务完成后（关闭智能搜索时也会触发）自动排队 |
| 候选查询 | 每条规则单独走自己的索引：连拍 ID 索引、文件名三元组索引、拍摄时间索引，再合并（`UNION`）。最初用一个 `OR` 写在一起，数据库会扫描该用户的全部照片，NAS 上十万张照片时每张都要全表扫描，已改掉 |
| 接口 | `POST /auto-stacks/run`（整理我的照片，`force` 时连移出过的也重新处理）、`DELETE /auto-stacks`（移除我的自动堆叠，返回数量）。权限沿用堆叠的创建/删除权限 |
| 网页 | 账户设置新增"自动堆叠"（开关、四条规则、相似度三档、拍摄间隔、保存、重新堆叠、移除所有自动堆叠）；管理 → 任务队列新增"自动堆叠"（缺失 / 全部，全部会二次确认）；en / 简体 / 繁体 |

## 端到端（`macos/scripts/m1_auto_stack.py`）

隔离测试实例（`local.immich-p5`，端口 2289/3009/5439/6386），智能搜索借用正式安装的机器学习服务和同一个模型，所以距离和正式库一致。素材是这台 Mac 上的真实文件：Sony A7C II 拍的 6 对 ARW+JPG，iPhone 的 8 张 HEIC（IMG_5566–5573，间隔 1–27 秒），用 `sips` 从 IMG_5571 做出的编辑版 `IMG_E5571.JPG`，另一天的一张 RAW 改名为 `CAM00074.ARW` 放在别的文件夹，以及 3 张写入了 Google 相机连拍 ID 的照片。全部放在模拟群晖的外部库里。

| 场景 | 结果 |
|---|---|
| 开启（默认规则）→ 扫描外部库 | 通过：11 秒内全部导入并处理完；6 对 RAW+JPG 各成一组，JPG 为封面；`IMG_E5571` 与原图一组，编辑版为封面；3 张连拍一组；别的文件夹里同名的 RAW **没有**被堆进去；没有多余的堆叠 |
| 上传一对 RAW+JPG（分别存到不同目录） | 通过：上传后自动堆叠，JPG 为封面（靠拍摄时间和相机型号认出是同一张） |
| 手动建一个堆叠（IMG_5566 + 5567） | 通过：之后所有操作都没有动它 |
| 打开相似照片（0.02 / 10 秒） | 通过：IMG_5572、5573（和 5571 相隔几秒）加入 IMG_5571 所在的堆叠，封面仍是编辑版；IMG_5568、5569、5570（相隔 10–27 秒）没有加入 |
| 从自动堆叠里移出 IMG_5573，再整理一次 | 通过：没有被放回去 |
| 移除所有自动堆叠 | 通过：9 个自动堆叠全部移除，手动堆叠保留，27 张照片一张不少 |
| 重新堆叠 | 通过：堆叠恢复，移出过的 IMG_5573 仍然不放回 |
| 任务队列"全部" | 通过：IMG_5573 也被重新堆叠回去 |
| 关闭自动堆叠后上传 | 通过：不堆叠 |

## 还没做 / 需要注意

- 规则判断的是文件名和拍摄信息，不看照片内容，相似照片规则除外。群晖导出时如果把文件改了名（例如加了序号），RAW+JPG 和编辑版就认不出来
- iPhone 原生连拍要在手机上"保留全部"后导出，才会带上连拍 ID；照片 App 只导出精选的那张时，连拍 ID 还在，但只有一张，不会堆叠
- 已经手动整理过的堆叠：自动堆叠只会往里面加照片，不会改封面
- 移动端 App 不需要改动，堆叠会正常同步显示
- 在真实群晖的照片上跑一遍（和网络共享、M1-5 一起），看相似度推荐值是否合适
