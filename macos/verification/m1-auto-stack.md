# 问题 2：自动堆叠

- 日期：2026-10-30
- 分支：`mac/feat/auto-stack`
- 结论：**通过**。每个用户在"账户设置 → 自动堆叠"里自己开启，并选择堆叠哪几类：连拍、RAW+JPG、编辑版、相似照片，相似照片还能设置相似度和拍摄间隔。每次上传和外部库扫描后在后台自动执行；管理员在"任务队列"里可以对所有开启了的用户统一执行。用真实照片跑端到端 34/34 通过，服务端单测 2495 项、网页单测 560 项全部通过

## 设计

| 问题 | 做法 | 原因 |
|---|---|---|
| 谁来设置 | **每个用户自己设置**（账户设置），管理员只管任务队列 | 堆叠是个人的整理习惯，规则因人而异；人脸识别那种全局开关不适合 |
| 什么时候执行 | 每张新照片处理完（元数据、缩略图、智能搜索向量都有了）后自动执行；保存设置时整理一遍现有照片；管理员可在任务队列里执行"缺失 / 全部" | 和人脸识别、重复检测一样走后台队列；队列并发为 1，同时到达的 RAW 和 JPG 不会互相抢 |
| 封面 | 编辑版优先 → JPG/HEIC 优先于 RAW → 收藏 → 评分高 → 像素多 → 拍得早 | 时间线上显示的应该是"成片"：相机出的 JPG、编辑后的版本 |
| 安全 | **只会往堆叠里加照片**：不删除照片，不把照片移出堆叠；手动建的堆叠只会被加入照片（包括并入一个自动堆叠），封面不会被改，两个手动堆叠永远不合并；自动生成的堆叠之间属于同一组时会合并；用户从自动堆叠里移出的照片会记住，以后不再放回去 | 堆叠是可以撤销的整理操作，但自动化必须尊重人工的决定 |
| 撤销 | "移除所有自动堆叠"：只删自动生成的堆叠（新增 `stack.isAutomatic` 字段区分），照片和手动堆叠都不动；"重新堆叠"：移除后按新设置重新整理 | 调整相似度时可以反复尝试，不用一个个手动拆 |

### 四条规则

| 规则 | 判断依据 | 默认 |
|---|---|---|
| 连拍 | 相机或手机写入的连拍 ID 相同（`BurstUUID` iPhone、`BurstID` Google 相机等，Immich 原来就会读取并保存，但从来没用过） | 开 |
| RAW + JPG | 文件名相同（不区分大小写）、一个是 RAW 一个不是；并且在同一个文件夹，或者（上传到不同目录时）拍摄时间相差不到 1 秒、相机型号相同 | 开 |
| 编辑版 | `IMG_E1234` ↔ `IMG_1234`（iPhone）、`IMG_1234-edited` ↔ `IMG_1234`（Google 相册导出）、`IMG_1234 (edited)`；照片配照片、视频配视频；同样要求同文件夹或同一时刻 | 开 |
| 相似照片 | 智能搜索（CLIP）向量距离 ≤ 阈值，**并且**拍摄时间相差 ≤ N 秒（1–3600） | 关；开启后默认 0.06 / 10 秒 |
| 相似照片 · 不限拍摄时间 | 距离 ≤ 另一个严格得多的阈值，不看时间：后来重新导出、另存、从别的设备传来的同一张 | 关；开启后默认 0.02 |

### 为什么相似照片必须加时间窗口

用这台 Mac 上的真实照片算了一遍 CLIP 距离：

| 照片 | 距离 | 间隔 | 实际 |
|---|---|---|---|
| IMG_5572 / IMG_5573 | 0.011 | 1.4 秒 | 同一场景连按 |
| IMG_5571 / IMG_5573 | 0.014 | 4 秒 | 同一场景连按 |
| CAM00074 的 ARW / JPG | 0.013 | 0 | **同一张照片** |
| CAM00087 的 ARW / JPG | 0.034 | 0 | **同一张照片** |
| CAM00082 / CAM00088 | 0.034 | 26 分钟 | 两张不同的照片 |
| IMG_5562 / IMG_5561 | 0.059 | 2 秒 | 同一时刻 |

同一张照片的 RAW 和 JPG 距离可能比 26 分钟后拍的另一张还大，所以单看相似度既会漏掉也会误堆。加上"几秒内"的限制后，阈值就可以放宽。

### 阈值修正（用户反馈：CAM00088 和 CAM00089 很像但没堆叠）

第一版三档是 0.01 / 0.02 / 0.03，按 iPhone 那几张（0.011–0.016）校准，对相机照片太严：CAM00088 和 CAM00089（相隔 3.4 秒）两张 JPG 距离 0.0455，同一张照片的 ARW 和 JPG 就有 0.034–0.06。统计了正式库里所有 60 秒内拍的照片对（不含 RAW）：

| 距离 | 10 秒内 | 10–60 秒 |
|---|---|---|
| < 0.03 | 4 | 2 |
| 0.03–0.05 | 5 | 3 |
| 0.05–0.08 | 13 | 4 |
| 0.08–0.12 | 9 | 3 |
| 0.12–0.2 | 2 | 0 |
| ≥ 0.2 | 4 | 28 |

几秒内的同一场景集中在 0.04–0.12，不同场景在 0.2 以上，中间有明显空档。三档改为：**严格 0.03、推荐 0.06、宽松 0.10**（可设上限 0.2）。

同时发现第二个原因：88 和 89 各自已经按 RAW+JPG 堆成了一组，而第一版"从不合并两个堆叠"，即使阈值合适也不会合到一起。改为：自动生成的堆叠之间属于同一组时合并；可以并入手动堆叠（只加照片、不改封面）；两个手动堆叠永远不合并。整理时也会重新检查自动堆叠里的照片，所以调整设置后点"保存"就会生效，不必"重新堆叠"。

### 不限拍摄时间（用户要求：隔很久但相似度极高也要堆叠）

不能简单地关掉时间条件：同一地点隔 26 分钟拍的两张**不同**照片（CAM00088 / CAM00082）距离只有 0.037，比"推荐"的 0.06 还近。所以改成两档并存：

- 几秒内：用"相似度"（0.03 / 0.06 / 0.10）
- 不限时间：另一个开关，用单独的、严格得多的阈值（仅完全相同 0.01 / 推荐 0.02 / 宽松 0.03，上限 0.1）

不限时间时沿 CLIP 向量索引（VectorChord）找最近的 20 张，再按阈值筛，不会扫描全库。实测：IMG_5568 缩小到 2048 像素、另存为 JPG、改名、日期改到一年后，距离 0.0029；IMG_5569 / IMG_5570（相隔 10.4 秒，几乎一样）0.019。注意：副本如果丢了方向信息（横竖颠倒），距离会变成 0.079，就不算"几乎一样"了。

注意：相似是逐对判断的，连续拍摄时（每隔几秒一张、持续几分钟）可能一张接一张串成一个较大的堆叠；场景一变、距离超过阈值，串联就会断开。

## 实现

| 部分 | 内容 |
|---|---|
| 数据库 | 迁移 `1793318400000-AddAutoStack`：`asset_job_status.autoStackedAt`（照片被自动堆叠的时间：之后它不在堆叠里，说明是被人移出来的），`stack.isAutomatic`。用 `sql-tools` 对比过，迁移和表定义一致 |
| 个人偏好 | `autoStack { enabled, burst, rawJpeg, edited, similar, maxDistance, maxSeconds }`，存在原有的用户偏好里 |
| 队列 | 新队列 `autoStack`（并发 1）：`AssetAutoStackQueueAll`（全部用户，或单个用户）、`AssetAutoStack`（单张照片）。新照片的智能搜索任务完成后（关闭智能搜索时也会触发）自动排队 |
| 候选查询 | 每条规则单独走自己的索引：连拍 ID 索引、文件名三元组索引、拍摄时间索引，再合并（`UNION`）。最初用一个 `OR` 写在一起，数据库会扫描该用户的全部照片，NAS 上十万张照片时每张都要全表扫描，已改掉 |
| 接口 | `POST /auto-stacks/run`（整理我的照片，`force` 时连移出过的也重新处理）、`DELETE /auto-stacks`（移除我的自动堆叠，返回数量）。权限沿用堆叠的创建/删除权限 |
| 网页 | 账户设置新增"自动堆叠"（开关、四条规则、相似度三档、拍摄间隔、保存、重新堆叠、移除所有自动堆叠）；管理 → 任务队列新增"自动堆叠"（缺失 / 全部，全部会二次确认）；en / 简体 / 繁体 |

## 端到端（`macos/scripts/m1_auto_stack.py`）

隔离测试实例（`local.immich-p5`，端口 2289/3009/5439/6386），智能搜索借用正式安装的机器学习服务和同一个模型，所以距离和正式库一致。素材是这台 Mac 上的真实文件：Sony A7C II 拍的 6 对 ARW+JPG，另外 2 对相隔 3.4 秒的 ARW+JPG（CAM00088、89），iPhone 的 8 张 HEIC（IMG_5566–5573，间隔 1–27 秒），用 `sips` 从 IMG_5571 做出的编辑版 `IMG_E5571.JPG`，另一天的一张 RAW 改名为 `CAM00074.ARW` 放在别的文件夹，以及 3 张写入了 Google 相机连拍 ID 的照片。全部放在模拟群晖的外部库里。

| 场景 | 结果 |
|---|---|
| 开启（默认规则）→ 扫描外部库 | 通过：11 秒内全部导入并处理完；6 对 RAW+JPG 各成一组，JPG 为封面；`IMG_E5571` 与原图一组，编辑版为封面；3 张连拍一组；别的文件夹里同名的 RAW **没有**被堆进去；没有多余的堆叠 |
| 上传一对 RAW+JPG（分别存到不同目录） | 通过：上传后自动堆叠，JPG 为封面（靠拍摄时间和相机型号认出是同一张） |
| 手动建一个堆叠（IMG_5566 + 5567） | 通过：之后所有操作都没有动它 |
| 打开相似照片（0.06 / 10 秒） | 通过：IMG_5572、5573（和 5571 相隔几秒）加入 IMG_5571 所在的堆叠，封面仍是编辑版；IMG_5568、5569、5570（相隔 10–27 秒）没有加入；CAM00088 和 CAM00089 两组 RAW+JPG（相隔 3.4 秒）合并成一组 4 张，封面 CAM00088.JPG；其余相隔更久的 RAW+JPG 保持分开 |
| 打开不限拍摄时间（0.02） | 通过：IMG_5568 一年后导出的副本（改名、缩小、另存 JPG）加入 IMG_5568；IMG_5569 / 5570（几乎一样，相隔 10.4 秒）堆叠；CAM00083（与 CAM00088 相隔 25 分钟、距离 0.056）没有加入；默认关闭时副本不堆叠 |
| 从自动堆叠里移出 IMG_5573，再整理一次 | 通过：没有被放回去 |
| 移除所有自动堆叠 | 通过：10 个自动堆叠全部移除，手动堆叠保留，31 张照片一张不少 |
| 重新堆叠 | 通过：堆叠恢复，移出过的 IMG_5573 仍然不放回 |
| 任务队列"全部" | 通过：IMG_5573 也被重新堆叠回去 |
| 关闭自动堆叠后上传 | 通过：不堆叠 |

## 还没做 / 需要注意

- 规则判断的是文件名和拍摄信息，不看照片内容，相似照片规则除外。群晖导出时如果把文件改了名（例如加了序号），RAW+JPG 和编辑版就认不出来
- iPhone 原生连拍要在手机上"保留全部"后导出，才会带上连拍 ID；照片 App 只导出精选的那张时，连拍 ID 还在，但只有一张，不会堆叠
- 已经手动整理过的堆叠：自动堆叠只会往里面加照片，不会改封面
- 移动端 App 不需要改动，堆叠会正常同步显示
- 在真实群晖的照片上跑一遍（和网络共享、M1-5 一起），看相似度推荐值是否合适
