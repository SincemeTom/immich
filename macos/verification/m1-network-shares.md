# M1-8 网页上挂载群晖（网络共享）

- 日期：2026-10-30
- 分支：`mac/feat/network-shares`
- 结论：**通过**。在"管理 → 网络共享"里填好群晖地址和共享文件夹路径，就能测试连接、添加和挂载。开机或服务重启时自动挂载；群晖重启、断网或句柄失效后会自动重新挂载。建外部库时点一下就能选已挂载的共享，不用再改 yml 或手动挂载。端到端 41/41 通过，服务端单测 2439 项、网页单测 560 项全部通过

## 怎么用

1. 群晖上先设置一次（页面顶部有同样的说明）：
   - 控制面板 → 文件服务 → NFS：启用 NFS
   - 控制面板 → 共享文件夹 → 选中照片所在的文件夹 → 编辑 → NFS 权限 → 新增：
     主机名或 IP 填 **Mac mini 的 IP**；权限选**可读写**；Squash 选"**将所有用户映射为 admin**"；勾选"**允许来自非特权端口的连接**"（Immich 以普通用户身份挂载，用的端口号大于 1024）
   - 对话框底部显示的"装载路径"（如 `/volume1/photo`）就是下一步要填的路径
2. Immich 网页 → 管理 → **网络共享** → 添加网络共享：填 NAS 地址、共享文件夹路径，名称会自动填上，可以改
3. 点"**测试连接**"：成功时列出共享根目录下的内容；失败时用中文说明原因和处理办法（见下表）
4. 点"添加"：挂载成功才会保存
5. 外部图库 → 添加文件夹：输入框下方会出现已挂载的共享，点一下就填好路径（例如 `…/Immich/mounts/群晖照片`），可以在后面再加子目录

第一次读取网络盘时，macOS 会弹窗问 node 能否访问网络宗卷上的文件，点"允许"就行（M1-7 之后只需点一次）。没点之前测试会提示"macOS 正在等待授权"。

## 实现

| 部分 | 内容 |
|---|---|
| 接口 | `admin/network-shares`：列表、添加、测试、修改、挂载、卸载、删除，仅管理员可用。服务端功能开关 `networkShares`，只有在 macOS 原生安装下才打开（Docker 版看不到这个菜单） |
| 存储 | 共享配置存在数据库的 `system_metadata`，随数据库备份一起备份。挂载目录在安装目录下：`~/Library/Application Support/Immich/mounts/<名称>`。目录名在添加时确定，之后改名不会改变路径，外部库的路径也就不受影响 |
| 挂载方式 | `/sbin/mount_nfs`，普通用户权限，不需要 sudo。参数 `soft,intr,timeo=10,retrans=5,deadtimeout=120,retrycnt=0,nfc,nobrowse,tcp`：群晖不在时操作会失败而不是一直卡住；`nfc` 统一中文文件名的编码；`nobrowse` 不在访达侧边栏显示。可选 NFS 版本（自动 / v3 / v4）和只读 |
| 所有系统命令 | mount、ls、df、umount 都在子进程里执行，并设了超时（挂载 30 秒、读取 10 秒、状态 5 秒），群晖没响应时不会拖住服务端 |
| 自动挂载 | 后台进程启动时挂载所有启用的共享，之后**每分钟检查一次**：<br>· 没挂上的 → 挂载<br>· 挂着但句柄失效（`Stale NFS file handle`，群晖重启后可能出现）→ 立即强制卸载再挂载<br>· 挂着但连续两次检查都没响应（群晖关机或断网）→ 强制卸载，之后每分钟尝试重新挂载；之所以要连续两次，是因为群晖硬盘休眠后唤醒需要一段时间<br>失败原因只在发生变化时记一次日志，不会每分钟刷屏 |
| 状态 | 已挂载（显示可用空间和总容量）/ 无响应 / 已卸载 / 挂载失败（附原因）。判断"无响应"用读目录而不用 `df`：群晖断开后 `df` 仍会返回缓存的数据（实测 7 秒后返回码仍为 0） |
| 卸载 | 手动卸载后会一直保持卸载状态，每分钟检查不会再自动挂载，适合群晖维护或关机前使用；想恢复时点"挂载" |
| 删除 | 有外部库在用这个共享时不允许删除；删除时先卸载，再删除**空的**挂载目录（用 `rmdir`，目录不空就不会删；仍挂载着也不会删） |
| 扫描保护 | 外部库扫描时，如果某个导入路径不能访问（没挂上时挂载点是空目录），这个路径下的照片保持原状态，**不会**标为离线。M1-6 已经保证清空回收站和过期清理时不删除不能访问的库的照片，加上这一条，群晖断开期间扫描也是安全的 |
| `immichctl uninstall --purge` | 先卸载所有网络共享，再删除安装目录；卸载不掉就停下来不删。否则读写挂载的群晖目录会被 `rm -rf` 一起删掉 |
| 网页 | 管理菜单新增"网络共享"页面（列表、状态徽标、容量、所属外部库、操作菜单，每 30 秒自动刷新）；添加/编辑对话框带测试连接；外部库"添加/编辑文件夹"对话框可以直接选择共享。新增 en / 简体中文 / 繁体中文三种语言的文案 |

### 错误提示

`mount_nfs` 的报错会被归类为以下几种，并在网页上给出对应的处理办法：

| 类别 | 典型报错 | 网页提示 |
|---|---|---|
| 连不上 | `Operation timed out`、`Connection refused`、`can't resolve host` | 检查地址、NAS 是否开机、是否启用了 NFS |
| 被拒绝 | `Permission denied` | NFS 权限里添加本机 IP、设为可读写、勾选允许非特权端口 |
| 路径不存在 | `No such file or directory` | 到共享文件夹的 NFS 权限页面查看装载路径 |
| 等待 macOS 授权 | 读取卡住、`Operation not permitted` | 在 Mac 上点"允许"，或到系统设置里打开 |

实测发现，主机名解析失败时 `mount_nfs` 最后一行同样是 `No such file or directory`，所以"连不上"要先于"路径不存在"判断（已修复并补了测试）。

### 第一次运行发现的问题

第一次运行 36 项中有 2 项失败，都在"群晖停止 → 恢复"这一段：

1. **"无响应"显示不稳定**：原来用 `df` 判断，群晖断开后 `df` 有时仍会立即返回缓存的数据，于是共享被显示为"已挂载"。现在改为读取共享根目录
2. **群晖恢复后一直不重连**：rclone 重启后，旧挂载上的所有文件句柄都失效了（`Stale NFS file handle`），但这个挂载仍然留在系统的挂载列表里，每分钟检查看到"已挂载"就跳过了。真正的群晖使用内核 NFS，重启后句柄一般保持不变，但重建卷、重命名共享文件夹之后同样会出现这种情况。现在每分钟检查也会读一下已挂载的共享：句柄失效就立即重新挂载；连续两次没有响应就强制卸载，之后每分钟重试

修复后重跑 41/41 通过。
