# 群晖照片相册同步：同步自己的相册

- 分支：`mac/feat/synology-albums`
- 日期：2026-11-04
- 结论：绑定了群晖账号的用户，他在群晖照片里自己的每个相册，都会同步成他在 Immich 里的一个相册，照片按路径从他自己的外部图库里找。每天定时同步（默认 03:00，可改），也可以在 账号设置 → 群晖照片 里点“立即同步”，下面显示上次同步的结果。只读群晖，不改动群晖上的任何内容；Immich 这边只动同步自己建的相册、只移出同步自己加进去的照片，照片本身从不删。服务器单元测试新增 52 项（群晖相关共 139 项）、数据库测试 9 项、网页新增 5 项（共 13 项）通过。用真实账号在正式服上同步还没做，见文末

## 怎么做的

| 部分 | 做法 |
|---|---|
| 读群晖 | 登录 → `SYNO.Foto.Browse.Album list` v1（带封面 `thumbnail`，每页 500）→ 每个相册 `SYNO.Foto.Browse.Item list` v1（`album_id`；读不到又有共享链接时改用 `passphrase`）→ 照片所在文件夹 `SYNO.Foto.Browse.Folder get` v1（每次同步每个文件夹只读一次）→ 登出。登录和登出跟“测试连接”共用一段代码，出错也会登出 |
| 哪些相册 | 只同步账号自己是所有者的相册（`owner_user_id` 是绑定时记下的群晖照片用户 ID） |
| 哪些照片 | 只同步这个账号自己的照片。别人加进相册的照片先只计数，在报告里显示“暂不同步”，等下一步做 |
| 找照片 | 群晖给的文件夹路径是相对个人空间 Photos 目录的（如 `/2023/旅行`），拼上文件名成相对路径。在这个用户自己的外部图库里（未删除的图库、不在回收站、不是实况照片的视频部分），找原始路径以“/相对路径”结尾的照片：先比完全一致，没有再不分大小写；两边都先做 Unicode NFC 规范化。对上多张时，优先大小一样的、在线的、路径最短的。直接放在 Photos 目录下的照片只有文件名可比，要大小也一样才算 |
| 建相册 | 第一次同步到、且至少找到一张照片的相册才建：名字用群晖的，封面用群晖的封面（找不到就用第一张），排序按用户自己的默认设置，所有者是这个用户。一张都找不到的不建，在报告里计数 |
| 记录 | 新表 `synology_album`（Immich 相册 ↔ 群晖相册，来自哪个账号，上次同步时群晖的名字和封面）和 `synology_album_asset`（同步加进去的照片）。相册、照片或用户删掉时，记录跟着删 |
| 改名、换封面 | 群晖改了名字才改 Immich 相册的名字；在 Immich 里自己改的名字，群晖不改就保留。群晖换了封面、新封面又找得到时才换 |
| 照片增减 | 群晖相册里有、Immich 相册里没有的加进去（在 Immich 里手动移出过的也会加回来，以群晖为准）；同步加进去的照片，群晖相册里没了就移出。在 Immich 里自己加进这些相册的照片不动 |
| 群晖删了相册 | 同步建的相册跟着删，照片还在，也还在别的相册里。群晖一个相册都没列出来、而以前同步过的时候，当作群晖出了问题，不删 |
| 读不到某个相册的照片 | 这个相册保持原样，不加也不移出，报告里计数 |
| 换了账号 | 同步只看当前绑定账号（地址 + 群晖照片用户 ID）建的相册；换绑别的账号后，以前账号建的相册留着，变成普通相册，不会被删 |
| 和手动操作一样的后续 | 加照片、移出照片后，和在网页上操作一样：更新相册的修改时间，没有封面时设封面，封面被移出时重新选，通知网页刷新（不发邮件），位置推断照常排队 |
| 任务 | `SynologyAlbumSync`，在后台任务队列里跑，同一用户排队中或进行中的不会再排一次 |
| 定时 | 微服务进程每分钟看一次：设定时间过了、而上次同步（或绑定、改时间、上次排队）还在那之前，就排一次。服务器关机错过了，开机后补一次。用服务器的本地时区。刚绑定或刚改的时间如果已经过了，等到第二天 |
| 报告 | 每次同步完存进绑定信息：开始和结束时间、成功与否和原因、相册数（新建、更新、删除、没建、读不到）、照片数（自己的、找到的、别人加的、加入、移出），以及前 20 张没找到的照片的群晖路径（后来改为完整清单，见 [synology-unmatched.md](synology-unmatched.md)） |
| 接口 | `POST /synology/account/sync` 立即同步（后台跑，马上返回）；`PUT /synology/account/schedule` 设 `autoSync`、`syncTime`（`HH:MM`）。`GET /synology/account` 多返回定时设置、下次同步时间、是否正在同步、上次报告 |
| 网页 | 账号设置 → 群晖照片，账号信息下面多一块“相册同步”：每天同步开关和时间、下次同步时间、上次同步的结果（没找到的照片可以展开看路径）、“立即同步”按钮。同步进行中按钮显示“正在同步…”，每 3 秒刷新一次结果 |

## 测试

| 测什么 | 结果 |
|---|---|
| 服务端单元测试：定时（每分钟检查、到点、没到点、刚绑定、改时间后等到第二天、只排一次）、立即同步、改定时、同步任务（没账号跳过、正常登录登出、密码错、钥匙串里没密码、群晖列不出相册、群晖一个相册都不列时不删、同步中被解除绑定）、换绑时保留定时和报告；路径拼接和查找（挂载位置不同、只在目录边界匹配、NFC、大小写、同名多张时怎么选、Photos 目录下的照片）；时间格式；两个新接口 | 新增 52 项，群晖相关共 139 项通过 |
| 数据库测试（真实 Postgres）：建相册和封面、一张都找不到不建、不用别人的 / 回收站里的 / 实况视频、群晖改名换封面增减照片（自己加的照片保留，手动移出的加回来）、Immich 里自己改的名字保留、群晖删了相册（照片和别的相册不受影响）、换绑后旧相册不动、读不到照片的相册不动、删用户跟着删记录 | 9 项通过 |
| 服务端全部单元测试 | 2838 项通过 |
| 网页：显示上次同步结果、同步失败的原因、立即同步后显示正在同步、改时间后保存、关掉每天同步 | 新增 5 项，共 13 项通过 |
| 类型检查、lint、格式；迁移和表定义一致（`sql-tools migrations generate` 显示没有差异） | 通过。网页 eslint 的 `tscompat` 规则照旧关掉（已有文件上也会崩溃） |

开发机没有 Docker，数据库测试用的是本机临时起的 Postgres（带 VectorChord），测试配置是临时的，没有提交。`library.service` 的数据库测试有 5 项在这台机器上不过，撤掉这次改动后一样，和这次无关。
